**3. 固定参考模型与梯度签名**

保留预训练结束参数：

\[
\theta_{\mathrm{ref}}=\theta_{\mathrm{pretrain}}.
\]

它在四个阶段中始终不变，仅用于探测，不参与优化，也不作为教师蒸馏模型。

第一版固定选择以下参数作为探测空间：

\[
\psi=
\{\text{最后一个时序解码器块的参数，动作头参数}\}.
\]

实际接入时导出参数名、形状和固定拼接顺序。若模块命名不同，以你的实现为准，但实验开始后不按效果更换探测范围。

对任务 \(k\)，计算：

\[
v_k=
\frac{1}{m}
\sum_{b=1}^{m}
\nabla_\psi
\mathcal L_{\mathrm{BC}}
\big(\theta_{\mathrm{ref}};H_b,a_b\big),
\]

\[
\widehat v_k=\frac{v_k}{\|v_k\|_2+\varepsilon_{\mathrm{num}}}.
\]

执行细节：

- **只使用原 BC 损失，不把 IFA 加入签名。** 这里希望测量专家动作要求模型怎样变化。
- 沿用原动作归一化、有效位置 mask 和 BC reduction。
- 先求各批次梯度的平均，再做整体归一化。
- 第一版不做逐层归一化、Fisher 平方或随机投影。
- 参考模型采用确定性的推理模式，关闭 dropout，但保留梯度计算。
- 用 FP32 累积梯度，不执行 `optimizer.step()`，不裁剪签名梯度。
- 参数没有参与该损失时，其对应梯度位置填零，不能改变拼接维度。
- 探测前后验证参考模型参数哈希不变。

TSR 原文是在固定 LoRA 初始化处计算梯度。这里采用固定预训练后端和原 BC，是针对 MLR 的适配，并非完整 TSR 复现。原理依据附件 §4.3.2、§5：

**4. 签名使用哪些样本、何时计算**

为避免“签名来自大量历史数据，而回放只有少量数据”的额外优势，**所有任务签名都基于该任务预定保留的五条示范**。

首轮建议固定：

| 新增参数 | 首轮值 |
|---|---:|
| 每任务探测 batch 数 \(m\) | 10 |
| 每个探测 batch 的窗口数 | 10 |
| 每任务探测窗口总数 | 100 |
| 轨迹分配 | 每条保留示范抽取 20 个合法窗口 |

这 100 个窗口只是探测抽样，不增加缓存容量。保持原窗口长度和合法索引规则；窗口不足时才允许重复采样，并记录实际唯一窗口数。相邻窗口不能被解释为独立演示。

时间安排：

1. 阶段 1 开始前，用六个基座任务的已有缓存计算六个签名。
2. 每个新任务到来时，根据该任务预定缓存示范计算签名。
3. 计算完当前签名后，再开始该阶段优化。
4. 后续阶段直接复用历史签名，不在已经更新的学生模型上重算。
5. 不提前访问未来任务数据。

为保证数据一致，缓存示范 ID 应由已有复现记录确定，并在对应任务到来时启用。如果基线未保存 ID，则必须使用与训练采样独立的缓存选择随机数流，并核对最终 ID。

签名探测、回放采样、缓存选择应使用独立 RNG。**不能因为多执行了若干次探测抽样，就改变当前任务的数据顺序或以后保留的示范。**

**5. V1 的回放概率与默认超参数**

设当前任务为 \(k\)，历史任务集合为 \(\mathcal O_k\)。计算：

\[
c_{j,k}=\widehat v_j^\top\widehat v_k.
\]

首先核对原代码实际的历史任务概率 \(p_0(j)\)：

- 若原实现按任务均匀采样，则 \(p_0(j)=1/|\mathcal O_k|\)；
- 若原实现是全缓存窗口均匀采样，则各任务概率可能与窗口数量有关，不能自行称其为任务均匀。

定义带原分布先验的路由：

\[
q(j\mid k)=
\frac{p_0(j)\exp(c_{j,k}/\tau)}
{\sum_{i\in\mathcal O_k}p_0(i)\exp(c_{i,k}/\tau)},
\]

\[
\boxed{
p(j\mid k)=
\epsilon p_0(j)+(1-\epsilon)q(j\mid k)
}
\]

当 \(p_0\) 任务均匀时，就是通常的余弦 softmax 路由。

首轮固定：

| 参数 | 值 | 含义 |
|---|---:|---|
| 路由温度 \(\tau\) | 0.1 | 初始设计值，参考 TSR；未证明对 OBJECT 最优 |
| 原分布覆盖比例 \(\epsilon\) | 0.5 | 至少保留每个任务原概率的一半 |
| 更新频率 | 每个增量阶段计算一次 | 阶段内概率固定 |
| 选中任务后的抽样 | 原任务内部采样规则 | 不增加关键帧筛选 |

**首轮只运行这一组参数，不先进行大规模搜索。**

其他规则提前固定：

- 保留余弦相似度的正负号。
- 即使全部余弦为负，也不宣称已找到正迁移来源；记录该现象，仍按预定路由运行。
- 当前签名无效时，整个阶段退回 \(p_0\)。
- 某个历史签名无效时，保留它的原概率质量，只在有效来源之间重新分配其余质量。
- softmax 使用数值稳定实现，记录最终概率和实际采样次数。

**6. 如何接入原训练循环**

原则是：**只在原代码需要抽取历史数据的位置替换来源选择。**

概念流程如下：

```text
加载同 seed 的共同预训练 checkpoint
固定 reference_model
加载历史缓存、任务清单和已有签名

对四个增量任务依次执行：
    当前任务到来后，计算其固定参考签名
    根据历史签名计算本阶段 replay_prob

    按原训练预算迭代：
        按原规则读取当前任务 batch
        按原规则确定历史样本数量
        使用 replay_prob 选择历史任务来源
        在选中的任务内按原规则抽取潜在窗口
        计算原 BC + 原 IFA
        执行原优化器更新

    按原规则保存和选择 checkpoint
    立即完成原协议的闭环评估
    按固定清单更新缓存
    将当前签名加入历史签名表
```

特别注意：

- 若原实现每个 replay batch 选择一个任务，就保留这一组织方式；若原本每个样本独立选来源，也保持对应粒度。
- 不增大 replay batch，不增加 epoch，不额外插入 replay-only 更新。
- 不用 \(1/p(j)\) 做重要性校正；V1 本来就是研究重新分配回放训练权重。
- 不改变 IFA 的任务对构造、margin、权重和归一化。

如果原 IFA 依赖当前 batch 中出现的任务，改变采样会连带改变 IFA 的实际曝光频率。此时应记录任务对出现次数和 hinge 激活比例；**不能声称实验完全隔离了 BC 路径上的影响。**

**9. 首轮判断与后续动作**

单 seed 阶段不做“统计显著提高”的结论。建议在运行前约定以下判断：

| 观察结果 | 后续动作 |
|---|---|
| AUC、最终成功率改善，新任务学习与保持没有明显代价 | 冻结配置，进入三 seed 复验 |
| 新任务表现提高，但 NBT／旧任务成功率明显变差 | 记录为迁移—保持权衡，V1 尚未通过 |
| 总体变化很小或指标方向混杂 | 判为不确定，不急于加入 CSG |
| 明显退化 | 回退，检查签名、概率集中程度与实现 |
| 概率几乎始终等于原分布 | 说明本次未形成有效来源选择，不能据此否定选择性回放原理 |

如果需要一个明确的初筛目标，我建议预先记录：**AUC 提高至少 2 个百分点，最终成功率不下降，FWT 不下降，NBT 增加不超过 1 个百分点**，作为进入复验的优先信号。它只是资源分配门槛，不是统计显著性标准；出现单个旧任务下降 10 个百分点及以上时，应额外检查对应 rollout。

不要根据首轮结果反复试温度直到上涨。如果需要修正，每次只改一个参数，记录全部尝试，避免把筛查数据当作无限调参集。

通过初筛后，冻结 V1 配置：

1. 扩展到 OBJECT 三个既有 seed，各自配对复用对应的预训练 checkpoint 和基线；
2. 按约定扩展到原论文其他套件，并保持各套件原配置；
3. 在 V1 被验证之后，才考虑 V2 的 CSG。

**本轮实际新增工作量：签名探测、一次 OBJECT 四阶段增量训练及对应闭环评估；基线训练全部复用。** 这次实验应首先确认“回放来源选择是否值得继续研究”，而不是提前为技能划分或新的损失函数承担验证成本。
