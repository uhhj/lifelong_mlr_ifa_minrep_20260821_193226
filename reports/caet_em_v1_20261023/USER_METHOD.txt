# 二、先修正当前代码的两个接口问题

## 2.1 最新帧读出：所有新实验组采用相同修正

当前 `BriefPolicy.temporal_encode()`：

```python
out = self.temporal_transformer(x)
out = out.view(B, T, M, E)
return out[:, :, 0, :]
```

最终动作使用最后一帧的第0个token。现有模态顺序和因果注意力下，这个读出不是完整的最新帧多模态读出。

本轮采用一个明确、容易审计的改法：

```python
tokens = temporal_transformer(x.flatten(1, 2))
tokens = tokens.view(B, T, 4, 512)

h_control = tokens[:, -1, 3, :]   # 最后一帧最后一个token
h_ifa = tokens[:, -1, 0, :]       # 原语言位置，继续用于原IFA
```

这样不增加第33个token，不改变八步、32个token的长度。控制读出能够访问当前帧之前的全部token；IFA仍沿用原位置和定义。

**必须同时修改训练策略和 `CompletePolicy.get_action()`。**只修训练读出、部署继续读第0个token，会形成新的训练—推理不一致。

这一修正可能本身改善性能，所以必须在直接动作对照中同样应用，不能把它算成CAET的独立贡献。

## 2.2 保留原GMM执行语义，但扩展严格加载

实际 `GMMHead` 的训练输出是完整混合高斯，部署选择最大logit分量，再从该分量的Normal分布采样；不是混合均值，也不是确定性均值。

新方法继续使用这一采样规则。

但原 `strict_downstream()`只核验Temporal和GMM两个前缀。新方法增加Effect预测器、条件解码器和归一化参数后，不能再用“原100个键加载成功”作为完整模型验收。应分开：

- `strict_base_init()`：核验官方预训练的原有参数；
- `strict_policy_restore()`：核验全部部署参数，任何新增参数缺失都报错；
- tokenizer和统计量通过独立SHA绑定。

# 三、数据契约：不重构物体状态，构建真实转移证据

## 3.1 时间索引

沿用已验证的缓存—演示身份绑定。缓存窗口结束于原索引 \(u\)，输入为：

\[
X_u=[o_{u-7},\ldots,o_u]
\]

预测第 \(k\) 个未来动作：

\[
A_u[k]=a_{u+1+k},\qquad k=0,1,2,3
\]

当前代码已通过演示ID、完整动作窗口、合法起点和填充规则核对这些对应关系；新标签器应复用身份绑定，不通过最近邻猜时间位置。

## 3.2 三类Effect证据

| 证据 | 首版定义 | 单步维度 |
|---|---|---:|
| 专家动作 \(A\) | 原7维控制命令 | 7 |
| 实际机器人响应 \(R\) | 7维关节状态＋2维夹爪状态的实际相邻变化 | 9 |
| 视觉变化 \(V\) | 两路冻结视觉特征的相邻变化，每路投影至32维 | 64 |

机器人响应使用真实记录：

\[
R_u[k]=r_{\mathrm{obs}}[u+1+k]-r_{\mathrm{obs}}[u+k]
\]

视觉变化：

\[
V_u^{(c)}[k]
=
P_c\left(
\Phi_c(I_{u+1+k})-\Phi_c(I_{u+k})
\right)
\]

其中 \(\Phi_c\) 是固定视觉编码器，\(P_c\) 是冻结投影。

**这不是物体位置重构，也不声称视觉差分就是物体位移。**视觉变化可能包含机器人运动、遮挡和视角变化；机器人响应与动作重构负责提供另外两类约束。

### 必须避免的导出错误

现有原缓存按训练模式和原增强流程导出。因此，**不能直接拿两个独立随机增强后的缓存向量相减，作为真实视觉变化**。

新增 `evidence.py` 应当：

1. 仅读取当前任务合法示范。
2. 使用固定空间编码器、部署一致的确定性预处理、`eval()`和关闭随机增强。
3. 提取两路图像在语言FiLM之前的视觉特征。
4. 对同一演示的相邻帧计算差分。
5. 将视觉编码器、预处理、投影和原帧索引全部绑定到标签清单。

原RA输入缓存不重写、不重新随机导出。

## 3.3 边界与记忆

分别保存 `action_mask[4]`、`response_mask[4]`、`visual_mask[4]`。轨迹末尾不足4步时只屏蔽缺失部分，不复制最后动作伪造未来。

第一步BC掩码与ALIGN一致；没有完整4步未来证据，**不意味着删除这个原训练样本**。

任务结束后，只为原RA选中的成员保留：

```text
sample_id / source_sha / demo_id / u
future_actions / masks
recorded_robot_response
frozen_visual_change
effect_target
tokenizer_sha / normalization_sha
```

后续任务只能读取这些保留成员及侧车标签，不重新扫描已丢弃的完整旧示范。额外侧车、tokenizer和教师缓存必须计入存储成本，不能称为严格等总内存实验。

# 四、模型：Effect必须位于实际动作生成路径

## 4.1 训练期Effect tokenizer

\[
E_u^*=T_\phi(A_u,R_u,V_u)
\in\mathbb R^{4\times64}
\]

首版配置：

| 部件 | 配置 |
|---|---|
| 三证据分支 | 各投影至64维 |
| 融合宽度 | 256 |
| 融合层 | 1层跨模态注意力 |
| 时序层 | 2层Transformer，4头，FFN512，dropout0 |
| Effect | 4×64 |
| 响应重构头 | Effect→4×9 |
| 视觉变化重构头 | Effect→4×64 |

tokenizer可以读取完整未来训练窗口，因为它只用于构建监督目标，不参与部署。这与AFCE的训练—部署信息分离一致。2610.13212v2

## 4.2 策略Effect预测器

\[
\hat Z_u=P_\theta(h_{\mathrm{control}})
\in\mathbb R^{4\times64}
\]

首版使用确定性MLP：

```text
512 → 512 → 4×64
```

\[
\hat E_u=\hat Z_u\odot\sigma_E+\mu_E
\]

归一化统计量固定，不逐任务重新估计。

这里没有照搬AFCE的流匹配。**确定性Effect预测可能平均化多模态未来，是首版需要检查的风险**；不能因为最后使用GMM，就认为Effect层一定没有多模态问题。

## 4.3 条件动作解码器

当前上下文：

\[
c_u=C_\kappa\big(X_u[-1,1:4,:]\big)\in\mathbb R^{128}
\]

它读取当前两路视觉和状态token，不读取专家动作、未来帧或真实效果。

每个Effect token与当前上下文、未来位置编码拼接：

\[
d_{u,k}
=
D_\psi([E_{u,k},c_u,\mathrm{pos}(k)])
\in\mathbb R^{512}
\]

原GMM Head生成：

\[
p(a_{u+1+k}\mid E_{u,k},c_u)
\]

建议解码融合为：

```text
Effect64 + context128 + position16 → 512 → 512 → 原GMMHead
```

**不增加从Temporal隐藏表示直接绕过Effect到GMM的旁路。**当前上下文仍可能让解码器忽略Effect，因此必须通过Effect置换／置零诊断检验，而不能从结构名称推断它已被利用。

部署过程固定为：

\[
X_u\rightarrow h_u\rightarrow\hat E_u
\rightarrow D_\psi(\hat E_u,c_u)
\rightarrow a_{u+1}
\]

只执行第一个动作，下一步重新预测。

# 五、解决持续学习中的tokenizer目标漂移

AFCE在全部离线训练数据上学习tokenizer，再冻结它和归一化统计量。我们不能预先使用Task7–9来完成这一步，否则破坏顺序学习的数据访问规则。2610.13212v22610.13212v2

## 首版采用：Task6初始化，之后完全冻结

Task6到达时：

1. 使用原10条演示中按身份排序的前8条训练tokenizer。
2. 后2条用于tokenizer重构验证。
3. 固定训练100个辅助epoch，batch64。
4. 按验证集总重构损失选择检查点，相同分数取最早者。
5. 用前8条训练数据计算视觉投影及归一化统计量。
6. 冻结tokenizer、视觉投影和统计量。
7. 主策略仍使用原10条演示训练，不减少正式BC数据。

阶段Ⅰ目标：

\[
\mathcal L_{\mathrm{codec}}
=
\mathcal L_{\mathrm{action\ reconstruction}}
+0.2\mathcal L_R
+0.2\mathcal L_V
\]

动作项使用GMM NLL，并附加0.1权重的分组Huber均值误差诊断性约束；位置、旋转、夹爪按组平均，避免维度数量决定权重。系数是本方案探索配置，不是AFCE原参数。

### 为什么先这样做？

它确保所有任务共享同一Effect坐标系，旧记忆不因tokenizer更新而改变含义。

代价也必须明确：**只在Task6训练的codec可能不能充分编码后续物体和操作。**因此每个新任务都要报告真实Effect的动作重构和响应重构误差；若后续明显恶化，结论应是固定codec的适用性不足，不能在当前实验中偷偷解冻重训。

本轮不因为没有达到任意物体定位精度而阻止闭环；只有数据身份错误、未来信息泄漏、数值异常或输出接口不可执行属于工程停止条件。

# 六、主训练：必须用“预测Effect”解码动作

\mathcal L_{\mathrm{BC}}
=
-\frac{

降低解码器学习率是参考AFCE“解码器适配但较慢更新”的原则；具体数值属于本方案设定。2610.13212v2

# 七、条件迁移：旧知识必须先能解释当前样本

不再直接按“两个Effect向量接近”把新旧控制表示拉在一起。

在Task \(t>6\) 开始时，冻结**本方法自身上一阶段**的策略与解码器：

\[
\bar P,\bar D
\]

对当前样本得到旧教师预测：

\[
\bar E_i=\bar P(X_i),\qquad
\bar q_i=\bar D(\bar E_i,c_i)
\]

构建两个可计算误差：

\[
r_A(i)=
\operatorname{GroupedHuber}
(\mu_{\mathrm{exec}}(\bar q_i),A_i^*)
\]

\[
r_F(i)=
\frac{
\ell(G_R(\bar E_i),R_i^*)+
\ell(G_V(\bar E_i),V_i^*)
}{2}
\]

其中 \(G_R,G_V\) 是冻结codec的重构头。

### 迁移启用规则

首版仅当以下条件同时满足才令 \(w_i=1\)：

| 条件 | 具体实现 |
|---|---|
| 观察条件有旧记忆支持 | 使用冻结视觉／状态特征检索旧RA成员；支持来自至少3条旧演示 |
| 动作可解码 | \(r_A(i)\le\tau_A\) |
| 未来证据可解释 | \(r_F(i)\le\tau_F\) |
| 数据合法 | 当前动作、响应、视觉标签及时间身份均有效 |

支持半径从旧RA记忆的跨演示近邻距离95分位数确定。

阈值在每阶段开始时只用旧RA记忆标定：

\[
\tau_A=\max(Q_{0.9}(r_A^{old}),0.02)
\]

\[
\tau_F=\max(Q_{0.9}(r_F^{old}),0.1)
\]

这些是观察数据上的启发式准入，不是因果正确性或闭环安全保证。阈值、支持率和各类失败原因全部记录，不根据正式成功率放宽。

迁移损失：

\[
\mathcal L_T
=
\frac{
\sum_{i\in D_t}w_i
\operatorname{Huber}
(\hat Z_i,\operatorname{sg}(\bar Z_i))
}{
\sum_{i\in D_t}w_i
}
\]

无有效样本时返回可微零。

**旧教师面对的是当前对象的观察，解码也发生在当前上下文；没有把旧物体的动作直接当成新物体标签。**当前样本自己的动作和真实效果始终保留为主要监督。

这本质上是“通过解码与效果证据筛选的知识蒸馏”，其独立价值必须通过消融证明。

# 八、历史功能保护：同时保护Effect解码和整条策略

本轮不恢复旧EFTR的“三候选＋固定编号KL”。

对每个旧RA样本，在阶段开始时缓存两个教师参考：

\[
q_{\mathrm{ref}}^{GT}
=
\bar D(E_i^*,c_i)
\]

\[
q_{\mathrm{ref}}^{Pred}
=
\bar D(\bar P(X_i),c_i)
\]

分别检查：

- **给定固定历史Effect，解码器是否还会执行；**
- **从旧观察开始，完整策略是否还会输出相近行为。**

## 8.1 比较实际选中分量，不锁死编号

当前和教师均按各自最大logit选择实际执行分量。相同编号不是保护目标。

对七维对角高斯使用分组Wasserstein形式：

\[
d(q,\bar q)
=
\frac12\operatorname{mean}_{d=1:6}
\left[
(\mu_d-\bar\mu_d)^2+
(\sigma_d-\bar\sigma_d)^2
\right]
+
\frac12
\left[
(\mu_7-\bar\mu_7)^2+
(\sigma_7-\bar\sigma_7)^2
\right]
\]

这里使用原归一化动作单位，不以当前预测方差为分母，不删掉夹爪差异。

保护损失：

\[
\mathcal L_F
=
\frac12d(q^{GT},q_{\mathrm{ref}}^{GT})
+
\frac12d(q^{Pred},q_{\mathrm{ref}}^{Pred})
\]

为让logit也获得行为相关的训练信号，可增加小权重路由项：

\[
\mathcal L_{\mathrm{route}}
=
\sum_k
\operatorname{softmax}(\ell)_k
\operatorname{sg}\big(d(q_k,q_{\mathrm{ref}})\big)
\]

它鼓励选择行为接近参考的分量，而不是固定分量编号。实际验收仍使用硬argmax后的真实输出，不用软分布代替部署行为。

## 8.2 完整目标

\[
\boxed{
\mathcal L
=
\mathcal L_{\mathrm{BC}}
+0.1\mathcal L_{\mathrm{IFA}}
+0.1\mathcal L_E
+0.02\mathcal L_T
+0.05\left(\mathcal L_F+0.1\mathcal L_{\mathrm{route}}\right)
}
\]

保护仅作用于合法旧RA样本，与当前阶段是否有迁移支持无关。

**这是软功能保护，不是硬信任域保证。**它可能保留旧教师错误，也可能抑制新任务塑性；必须报告旧任务绝对成功率和新任务学习结果，不能只报告距离下降。

# 九、实验分组：首轮三组，后续消融预先定义

## 9.1 首轮默认执行

## 12.2 科学诊断

每阶段分别保存：

1. **GT-Effect动作重构**：真实Effect经过当前解码器，能否恢复专家动作。
2. **Predicted-Effect动作误差**：预测Effect经过同一个解码器，误差增加多少。
3. **模态干预**：动作、响应或视觉证据被置换后，tokenizer及解码结果是否变化。
4. **Effect使用检查**：置零或置换Effect后，动作是否几乎不变；若不变，应报告解码器可能绕过Effect。
5. **迁移和保护账目**：支持率、准入失败原因、教师误差、旧执行距离及模式行为变化。

这些原则来自AFCE对重构、真实Effect解码和预测Effect闭环的分层验证；其论文也显示，预测Effect的动作读出误差可能远高于真实Effect读出误差。2610.13212v22610.13212v2

**不在正式rollout中读取演示未来Effect。**本轮GT-Effect验证限定为离线诊断，不依赖已经出现恢复问题的历史MuJoCo精确重演。

## 12.3 正式结论

主指标保持项目AUC定义：

\[
\mathrm{AUC}
=
\frac14\sum_{j=6}^{9}
\frac1{10-j}\sum_{i=j}^{9}r(i,j)
\]

同时报告FWT、NBT、OldFinal、FinalAll、每个单元的成功次数及任务轨迹。

现有seed41的ALIGN AUC为81.4583%、OldFinal为70%、FinalAll为75%，仅作为已完成参照；新方法最重要的是相对新匹配对照B0及EM核心组的增量。

解释规则：

- **B1＞B0**：可执行Effect接口具有正向证据。
- **B2＞B1**：条件迁移与功能保护组合具有正向证据。
- AUC提高、OldFinal下降：报告权衡，不宣称防遗忘成功。
- Effect预测改善、闭环不改善：不能宣布模块有效。
- 单seed改善：仅作为开发证据，冻结后再扩展其他seed，不声称统计显著。

# 十三、执行顺序与命令接口

推荐实际顺序：

**资产冻结 → 当前Task6证据导出 → codec训练与冻结 → 各组独立四任务训练 → 原协议闭环 → 独立复算。**

以下是需要实现的命令接口规格，不是仓库现成可执行命令：

```bash
# 1. 固定源码与OBJECT seed41父资产
python -m caet_em_exp.prepare \
  --suite OBJECT --seed 41 \
  --config configs/caet_em_v1.yaml

# 2. 仅Task6当前数据：证据与codec
python -m caet_em_exp.evidence --task 6
python -m caet_em_exp.train_codec --task 6
python -m caet_em_exp.audit_codec

# 3. 每组在独立输出目录完成全流程
for ARM in READOUT_BC4 EM EM_TF; do
  python -m caet_em_exp.preflight --arm "$ARM"
  python -m caet_em_exp.pipeline --arm "$ARM"
  python -m caet_em_exp.audit --arm "$ARM"
done

# 4. 从完整正式episode记录重算并比较
python -m caet_em_exp.compare \
  --arms READOUT_BC4 EM EM_TF
```

`pipeline`必须按任务到达顺序导出当前证据、读取合法旧记忆、训练100epoch、保存epoch99、执行原RA入库；不能在Task6前预先拟合全部四任务的投影、tokenizer或统计量。

所有组共用只读原缓存，各自拥有独立模型、Buffer、侧车、日志和恢复状态。工程故障留证并从完整状态恢复，科学负结果不重跑覆盖。
