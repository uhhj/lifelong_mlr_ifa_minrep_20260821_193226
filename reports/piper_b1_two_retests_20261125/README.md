## 哪个环节先偏离

第一轮启动后 1.10 秒，ODE 预测的八步序列已包含收爪动作，执行台结束横向纠偏。此时最后一次桌面距离估计仍有 18.30 mm。实际开度从 61.6 mm 收到 37.6 mm，说明夹爪确实动作过。进入等待时宽度满足 35–44 mm 的范围，力矩没有达到用于确认夹持的 −1.20 至 −0.80 N·m。腕部画面中，木块在画面下沿，只看到部分木块；配对成功示范中，木块侧面已经贴近两指内壁。记录支持接近或夹指插入深度不足，也允许短暂轻触的可能。

第二轮退出横向纠偏时的距离估计更小。首次下发开度 ≤55 mm 时，TCP 高度比同批 48 条可比成功示范中的最高值还高 4.31 mm；相应专家高度的中位数为 −2.98 mm、范围为 −12.79 至 +14.27 mm。到进入等待时，TCP 已降至专家收爪高度附近。这些值来自同一套关节正运动学与工具标定。腕部画面和现场观察均能把木块放在两指之间，但其影像在画面里仍低于配对成功示范，实际开度也停在 55.2 mm，宽度与力矩两项条件都未达到。现有材料不能区分插入深度不足、单侧阻挡和当前模式下的夹爪执行响应。桌面投影距离无法单独衡量三维抓取姿态。

## 等待为什么不起恢复作用

两轮进入等待前，开度已分别约 0.20 秒和 0.27 秒保持在最终读数的 0.11 mm 内。收爪响应变弱先于等待。等待期间，执行器保持六轴上一条目标，同时将新的夹爪请求限制为 `min(上一条目标, max(模型预测, 实测开度 − 6 mm))`。代入本轮数值，第一轮实测需先收至 30.62 mm 以下、第二轮需先收至 48.42 mm 以下，才可能继续下调目标。两轮各有 61 次等待发送；逐组复算，七维目标全部重复。每轮都查到了 121 个去重后的相机采样或发送前反馈时戳，没有一个同时满足宽度和力矩条件。延长等待无法改变这段记录的目标序列；超过 2 秒后的物理响应则未知。[收爪判定实现](../piper_b1_grip_window_20261125/grip_window.py)

## 其他链路与证据边界

- 266 组现场目标均有 SDK 四个 CAN ID 的提交成功记录，输入图像、预测和反馈均按时戳逐组对齐。驱动反馈状态均为 0x40。六轴与上一已发目标的最大偏差分别为 1.94° 和 1.54°；双相机最大时差分别为 8.74 和 17.66 ms；发送前夹爪反馈的最大年龄分别为 5.26 和 5.13 ms。两轮的首个停机事件均来自夹爪等待到期。独立 CAN 抓包没有覆盖这两个时段，因此只能确认 SDK 提交与实际反馈，无法验证控制器逐帧接收了哪些目标。
- 已安装 SDK 的宽度模式以 0.001 mm 为单位；测试台换算后使用力度字段 1000、宽度使能码 1。现场驱动没有开启 SDK 可选的夹爪行程裁剪。力度字段为指令参数，实际反馈力矩由另一条报文单独返回。现有力矩参考来自官方直连示教，当前普通 CAN 模式下尚缺一次已知成功夹持作参照。
- 在同批 48 条可比示范中，对每轮的起始、首条目标 ≤55 mm 及等待姿态按六轴反馈分别找最近帧，固定俯视画面的桌面线孔和紫纸角在六组配对中均未检出位移（2 像素搜索步长）。配对姿态仍有 0.93°–2.43° 的关节均方根差，名义 TCP 差可达 21.73 mm。这些图像支持核对真实夹指、木块与桌面的相对位置，无法据此断定底座移动或关节零位改变。另选了每轮在首次目标 ≤55 mm 时姿态最接近的三条成功示范，比对该时刻和专家实测首次 ≤42 mm 时的腕部画面；第二轮现场实测始终没有到 42 mm。

**优先区分两个问题。** 用现有普通 CAN 模式，在现场固定姿态，分别空载复现相同收爪过程、再在确认夹指对中且深度正确时夹同一木块，保留下发目标、实际开度、力矩、状态和腕部画面。如果空载同样差约 13 mm，应先核查控制器实际收到的指令与夹爪位置响应；如果空载跟随、对中时能稳定夹紧，则应先改策略从接近转入收爪的条件，并用普通 CAN 的成功接触记录复核力矩阈值。两轮分析仅使用归档。
