# 原始采集资产与物理版本诊断

沿用原3个固定窗口、动作记录、XML数值、阈值。0训练、0策略续跑。
历史物理转移1e-5、低维观察1e-6、完整快照重复1e-10均不变。

官方LIBERO采集脚本最早公开提交为2023-06-07；MuJoCo2.3.5于2023-04-25发布，
2.3.6于2023-06-20发布。故在看到新物理测试结果前，选2.3.5作为公开初期
可用的历史候选，与现用3.2.3对照。不能称其为已确认的实际采集版本。
不扫描版本挑最低误差；不修改现有site-packages、模型XML数值或物理参数。
2.3.5以独立目录和独立Python进程加载，依赖仍用现有环境。

每版本对固定3条演示：
1. 按现有方法携带控制器/积分隐状态，逐步注入已记录坐标重建已知前缀，
   至各固定target，共155控制步。这是工程诊断，不能充当无干预历史复现。
2. 保存完整新快照，对下一条记录动作重复2次（6控制步），验证重复恢复。
3. 从相同记录坐标与相同初始零隐状态开始，执行同一组逐物理子步ctrl：
   3.2.3记录一次生成的ctrl，2.3.5直接重放它，隔离控制器策略的版本间影响。
   各3个控制步；ctrl载荷仅留远端，不发布下载。
4. 在已恢复坐标处检查派生EEF在forward前后及历史记录观察的差异。
   不通过改观察定义或删除某坐标来通过门槛。

每版本最多164工程控制步；不计为54条策略续跑。所有技术尝试独立留证。
若仍失败，维持BLOCKED，保留具体原因和未识别因素。不能用新版本较好即跳过
完整历史恢复、native GMM接口与原54条准入条件。
