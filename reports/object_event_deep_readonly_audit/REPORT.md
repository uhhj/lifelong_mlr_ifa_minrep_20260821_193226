# Event负效应深度只读审计与改进价值判断

本轮只读检查首次seed40–44的现有事件日志、窗口绑定、C/EC入库清单、epoch日志及原示范动作。没有加载模型权重、运行优化器、重算选择器或执行闭环；没有改变原run。远端脚本只写/tmp分析输出，结果下载到本目录。

结论：当前“确认事件窗口至少占50%”方案缺乏继续长跑的依据。事件元数据仍有诊断价值；改成“只修补经验证的事件/阶段覆盖缺口，且约束覆盖代价”的新问题有有限研究价值，但在当前任务上可能几乎退化为原Coreset，不能预期一定有明显提升。

## 1. 新发现：提高事件窗口数量，没有增加参与后续训练任务的事件覆盖

覆盖定义为：一个确认事件区间至少有一个已保存窗口的监督末步落在该区间。它不等于技能完整覆盖，更不等于已掌握该操作。

|任务|每seed确认事件数|C已覆盖事件数，seed40→44|EC覆盖数|五seed合计新增窗口|新增覆盖事件数|
|---|---:|---|---|---:|---:|
|6|56|56/56/56/56/56|相同|0|0|
|7|74|71/71/72/70/70|相同|41|0|
|8|62|62/62/62/62/62|相同|230|0|

Task7/8的271次新增入库选择全都落在原C已覆盖的事件内。Task7有少数1–3步的短事件仍没有代表窗口，增加事件总数没有修补它们；其中另有一个demo_2的[5,6]事件没有监督末步候选，不能把这种不可表示的缺口归咎于选择器。

新增大部分落在较长事件，但这不是相对于候选机会数归一化后的“偏好长事件”检验。更确定的事实是：现有目标只约束事件窗口总量，不约束事件实例覆盖或同一事件的边际价值。

Task9新增95–113条确实补了2–3个此前未覆盖事件（另有一个没有候选），但入库发生在最后一次训练之后，本轮没有后继任务使用它们，不能将这些诊断改善算作模型收益。

## 2. 被排除的“普通”窗口并不等于无用静止数据

Task8五seed合计230次替换，按每次入库选择计数（不当作230个独立物理样本）：

- 被移除窗口末步闭合夹爪命令占64.35%；新增窗口为45.65%。五seed逐一比较，均是移除集合的闭合命令比例更高。
- 被移除窗口的平移命令RMS均值0.42870，新增为0.31267；五seed方向一致。此为归一化控制命令幅度，不是物体真实运动速度。
- 118/230个被移除窗口位于某个确认事件前或后7步内（51.30%）；Task7为31/41（75.61%）。7步取自原8步窗口上下文，不按表现调参。
- Task8保存目标时刻的相邻对数增加18–32对/seed，表明时间邻近性增加；不等于精确重复窗口，也不能据此直接断言无信息。

现有标签仅看target_step是否位于事件内。事件之后的窗口即使包含事件历史，也可能被当成普通窗口；稳定保持、移动到下一个状态和事件结束附近的控制不会因其重要而自动获得配额。代码中的夹爪事件结束在稳定确认块之前，本来就不保证保留动作后的稳定控制。

这些数据支持“新增事件窗口改变了控制内容和时间密度分布”的机制线索。它们不能证明被移除窗口一定对应持物运输/成功抓取：闭合命令不是抓住物体的传感器证据，需要对象/接触/轨迹信息才能作出那种语义结论。

## 3. 覆盖代价与时间上的学习损失吻合，但没有唯一因果识别

上一轮60份元数据核查已发现：Task8全局覆盖半径增加3.79%–6.07%，最差覆盖落在普通窗口池。此次发现C已覆盖所有Task8事件，因此事件数量上升的增量价值更可疑，而覆盖代价是可见的。

但是，“半径增加导致Task9失败”仍不是已证明的因果链。seed43替换数量比多个seed少，AUC降幅却最大；结果不符合简单的替换越多、下降越大的解释。

全部五seed在Task6/7的100条epoch loss日志逐值一致；首次差异均出现在Task8 epoch0。这里只用日志定位差异开始时间，不用loss定义行为受损。此前C/EC的阶段6/7评估矩阵也一致。Task7入库在其训练后生效，时序上完全符合Task8开始分叉。

Task8入库只能影响Task9训练，不能解释Task8刚学完时的差异。Task9入库不影响本轮任何已训练模型。Task8/9两阶段IFA选中对都为空，不能将C/EC差异归于不同IFA配对。

## 4. 新发现：小幅成员替换产生了大幅训练位置改变

原加载器先按文件名字典序列出buffer，拼接当前任务样本，再用相同seed shuffle；DistributedSampler施加相同索引置换。插入/删除少数文件会移动大量共同成员的位置。

|seed|Task7替换数|训练Task8时完整数据集不同位置比例|Task7+8累计替换数|训练Task9时完整数据集不同位置比例|
|---|---:|---:|---:|---:|
|40|6|20.06%|56|34.61%|
|41|14|20.55%|64|37.71%|
|42|7|11.68%|58|29.12%|
|43|5|16.49%|44|34.83%|
|44|9|17.72%|49|34.12%|

这里精确计算的是共同置换前的样本身份位置差；对相同完整置换，该差异数保持不变。未宣称以上百分比等于“受影响batch比例”，也未额外迭代正式sampler。当前样本位置和任务槽位标签保持一致，改变的是同一旧任务内部的样本身份和共同成员位置。数据数量和完整遍历预算没有变化。

例如seed43 Task7只替换5个成员，但训练Task8的3081个数据位置中508个不同，其中503个是仍保留的旧样本换了位置。因而“只替换5个，所以训练扰动一定很小”不成立。这是既有排序加载机制与成员变化相互作用的结果，不是发现了违规重排或额外训练。

现有实验改变了样本集合，也改变了共同样本参与batch的安排。再加上原动作采样使用全局RNG，不能将闭环差异全部解释成事件内容的好坏，也不能认定全部是顺序噪声。需要将这项混合效应纳入结论边界。

## 5. 当前方案的研究价值

不建议继续把当前50%事件窗口配额当作主候选，亦不建议现在用这五seed成功率寻找更优rho、检测阈值或窗口宽度。当前证据否定的是这项具体配额干预的稳定增量收益，不是所有事件表征。

事件元数据值得保留：它已经能揭示C覆盖了什么、遗漏了什么以及哪些普通窗口被挤出。若继续设计，应把问题从“事件占比够不够”改成“经过语义核验的操作阶段或事件边界有没有真实覆盖缺口”。

可考虑的方向只限后续设计，并未执行：

1. 以事件实例或有因果意义的操作阶段为单位识别缺口，而非按事件窗口总数硬加权；已有覆盖充分时明确不干预。
2. 先核验接触/物体响应和转换前后状态，再决定需要保护什么；不能将夹爪命令直接解释为抓取成功。
3. 同一记忆预算下加入全局覆盖与非事件区域覆盖约束，拒绝为了达配额而无条件牺牲原覆盖。容差须在后续运行前固定，不能根据当前成绩挑选。
4. 如果要识别样本内容效应，需单独设计并披露共同成员位置保持的对照；这改变了当前加载实现，不能悄悄混入旧协议，也不能直接当作现有实验已证明的结论。

在当前Task8中全部62个确认事件已有代表，按“补缺口”设计很可能不作任何改变。Task7确实有少数可表示但未覆盖的短事件，但其任务关键性尚未被验证。因而其后续价值是有限、条件性的，不支持现在就投入又一轮完整五seed训练。
