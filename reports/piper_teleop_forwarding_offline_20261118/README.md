# PiPER 转发修复与离线验收

2026-11-18（北京时间）完成离线验证。验证通过后备份并更新现用转发程序，逐文件核对安装哈希。安装前后 `can0`、`can1` 均为 `DOWN`，未启动上位机、遥操进程或机械臂。现场短测待进行。

## 变更

- 六轴目标只从 `0x155` 开始，随后接收 `0x156`、`0x157`。新首帧抛弃旧的未完成组，异常或超时的分包不会更新已完成目标。未组齐满 50 ms 沿用既有保护停止路径。
- 组内时窗设为 3 ms。历史上 10,991 组有序且与已记录目标一致的快照，跨度中位数为 0.305 ms，P99 为 0.424 ms，最大为 0.535 ms。协议没有组序号，极端多帧丢失仍受可观察顺序和时窗限制。现场短测需复核真实发送节奏。
- `can_timeline.jsonl` 按同一主机单调时钟 `mono_ns` 记录主臂原始报文、从臂原始反馈、精确下发的目标帧、SocketCAN 接收结果及独立接收套接字读到的本机 `can0` 发送回显。目标事件含 `source_mono_ns`，可关联对应主臂组尾帧或夹爪帧。发送回显与从臂执行反馈分开记录。既有 `samples.jsonl` 继续保留。

## 离线复核

- 在服务器上的隔离目录运行 43 项后端测试，全部通过。测试入口禁止打开物理 CAN 套接字。覆盖新首帧到达、丢任一分包、乱序或重复分包、超时、目标原样下发以及发送失败与回显区分。
- 重放 10,991 组历史已记录的完整目标，解码结果全部一致。日志线程按每秒 3,000 条的名义速率写入 9,000 条模拟事件，记录数量与顺序均一致。
- 已核对补丁能应用到原始源码副本。服务器安装后的 `core.py`、`transport_base.py` 和 `worker.py` SHA-256 前缀分别为 `51a95298c084`、`715e9daa8e1d` 和 `4f79609dd1f1`。

现场短测时，用同一轮 `can_timeline.jsonl` 检查静止持位和低速跟随，核对主臂输入、实际总线回显与从臂反馈的时序。本次结论限于离线验证，尚未验证真机回显或确认 J4 抽动是否消失。 [SocketCAN 本机回显语义](https://docs.kernel.org/networking/can.html#local-loopback-of-sent-frames)
