# 建议的下一代方案：闭环结果驱动的互补策略残差

结合 ZR-v1～v3、SAZR、夹爪分类头及最新 CZR 实验，我建议不再让残差从专家演示中重新学习父策略已经掌握的动作，而是利用其他已训练策略中的有效控制行为，通过真实闭环结果选择、验证并学习有益修正。

暂称 OVR：Outcome-Verified Residual Transfer（闭环验收驱动的残差迁移）。

这与前几轮有一个根本区别：

- 之前：父策略与专家标签不一致 → 尝试修改动作。
- 新方案：另一策略能够在同类任务上成功 → 将其作为候选控制行为来源 → 通过独立闭环验证 → 再迁移为残差。

目标是直接提高闭环 AUC、FWT 和最终旧任务成功率，而不仅是降低离线误差。

必须说明：目前没有任何新残差能被现有数据保证提高闭环成绩。下面的方案是基于已观察到的策略互补性提出的，更有依据的待验证方向，而不是已确认有效的算法。

## 一、重新分析已有数据：其实存在一条此前没有充分利用的正向线索

前几轮实验已经形成三个相当明确的事实。

| 实验         | 已确认的结果                        | 对新设计的启示            |
| ---------- | ----------------------------- | ------------------ |
| ZR-v2、v3   | 训练 NLL 下降、KL 约束成立，闭环仍可能下降     | 不能继续将离线拟合作为残差有益的证明 |
| 夹爪 Stage A | 父策略原生夹爪标签已非常准确，全面替换增加错误       | 必须保护父策略已有能力        |
| CZR        | 训练记忆内纠正23/23，但跨演示0/23、独立留出0/4 | 静态特征邻域无法可靠传播局部纠错   |

参考：[ZR-v3 分析](https://github.com/uhhj/lifelong_mlr_ifa_minrep_20260821_193226/blob/d87f60ef0243a37c70d21c8a56e0a38f6f7076cc/reports/zrv3_object_seed41/task6_readonly/REPORT.md?utm_source=chatgpt.com)、[CZR 跨演示诊断](https://github.com/uhhj/lifelong_mlr_ifa_minrep_20260821_193226/blob/d87f60ef0243a37c70d21c8a56e0a38f6f7076cc/reports/czr_stageA_object_seed41/readonly_generalization/REPORT.md?utm_source=chatgpt.com)。

### 一个额外值得利用的数据发现：不同策略的成功轨迹确实互补

我进一步从已发布的逐 episode 记录中，核对了 OBJECT seed41、Task 6 在不同训练阶段的成功初态集合。

| 已完成阶段  | RA 成功 | Coreset 成功 | Random 成功 | 三者成功初态并集 |
| ------ | ----- | ---------- | --------- | -------- |
| Task 6 | 12/20 | 10/20      | 10/20     | 14/20    |
| Task 8 | 7/20  | 9/20       | 8/20      | 16/20    |
| Task 9 | 9/20  | 6/20       | 3/20      | 14/20    |

这些记录的初态哈希已核对一致。

例如，阶段8时 RA 只有35%的 Task 6 成功率，但 Coreset、Random 在 RA 失败的部分初态上成功。到阶段9，RA 自身成功45%，三组策略的成功初态并集则达到70%。

这些并集数值是事后知道每条轨迹成功与否的理想选择上界，不是任何当前方法已经实现的成功率，更不能用正式测试标签来选择策略。 不同训练运行和动作随机流也限制了严格因果解释。

不过，它提供了值得检验的方向：与其凭专家动作差异猜测怎样修复父策略，不如利用已经展示过成功行为的其他策略，提出更有根据的候选动作修正。

## 二、优先利用哪种互补策略？我建议先利用历史成功模型

虽然 Random、Coreset 和 RA 之间存在互补性，但把三套完整策略都引入新模块，会增加模型数量和训练成本。

更适合当前持续学习问题的第一选择，是同一训练序列中以前保存的高性能阶段模型。

这条路线甚至有更直接的数据支持。

### 以 OBJECT 的 Task 6 为例

| Seed | RA 在 Task 7 训练结束时的 Task 6 成功率 | RA 在 Task 9 训练结束时 | 下降     |
| ---- | ----------------------------- | ----------------- | ------ |
| 41   | 85%                           | 45%               | −40 pp |
| 42   | 80%                           | 10%               | −70 pp |
| 43   | 65%                           | 50%               | −15 pp |

三个 seed 都存在以前的模型完成 Task 6 更好的现象。

这说明一个非常具体的研究机会：

> 当训练 Task 9 后，最新共享策略遗忘了 Task 6，为什么不让一个小型零响应残差恢复 Task 7 结束时已经学会的 Task 6 控制能力？

与前几轮不同，这次残差不需要重新猜测专家在某个状态应该怎么操作。

我们已经有一个真实训练过、曾经取得较高闭环成功率的历史策略，它可以提供完整的动作决策。

例如 seed42：

- 当前 Task 9 模型执行 Task 6：10%。
- 之前 Task 7 模型执行 Task 6：80%。

这不保证旧模型在新的独立初态上仍优于当前模型，但值得优先验证。

如果能够把这种历史能力迁移到当前策略，而不改变 Task 9 的行为，就可能同时改善旧任务 AUC 和最终旧任务成功率。

来源：[OBJECT RA 完整成功率矩阵](https://github.com/uhhj/lifelong_mlr_ifa_minrep_20260821_193226/blob/d87f60ef0243a37c70d21c8a56e0a38f6f7076cc/reports/object_ra_conditional/launch/FINAL_REPORT_20261020.md?utm_source=chatgpt.com)。

## 三、OVR 的具体算法设计

我建议第一版将 OVR 收敛成更明确的实现：

历史成功策略蒸馏＋阶段独立残差＋闭环验收。

### 1. 冻结当前公共策略

假设当前完成 Task \\(k\\)，得到：

\\[ \pi_k^P(H,e). \\]

它就是原来的 Coreset／RA＋IFA 策略。

不修改公共网络，不重新执行100轮训练，也不修改原 Buffer。

当前新任务 \\(k\\) 直接使用原策略：

\\[ \boxed{\pi_k^{OVR}(H,e_k)=\pi_k^P(H,e_k).} \\]

这是一条重要设计约束。

此前 ZR-v1、v2、v3 经常出现新任务刚完成学习就退步的问题。OVR 第一版不修正刚学完的新任务，因此在同一父 checkpoint、同一推理与采样协议下，FWT 应当与父模型完全一致。

这避免了过去最常见的一类负贡献。

### 2. 为需要恢复的旧任务寻找历史教师

对于旧任务 \\(j\<k\\)，候选教师来自此前已经保存的阶段模型：

\\[ \mathcal T\_{k,j} = \\{\pi_j,\pi\_{j+1},\ldots,\pi\_{k-1}\\}. \\]

教师不能使用任何未来任务的信息。

使用独立开发初态的真实闭环成功率比较历史教师与当前父模型。只有确实观察到教师优势，才进入残差蒸馏。

例如在 seed42、阶段9、Task 6 的探索性原型中，可以预先指定 Task 7 阶段快照为教师。这个选择受到历史结果启发，因此属于探索性验证，不是独立确认实验。

如果教师在新的开发状态上没有明显优势，应停止，不训练该残差。

### 3. 在教师成功轨迹上学习策略差异

给定相同历史 \\(H\\)，分别计算：

\\[ \pi_k^P(H) \\]

和历史成功教师：

\\[ \pi\_{t^\*}^{T}(H). \\]

残差目标不是专家示范动作与父策略之间的误差，而是：

\\[ \boxed{ \Delta^\*(H) = \mu\_{t^\*}^{T}(H)-\mu_k^P(H) } \\]

其中 \\(\mu\\) 表示两策略真正执行的所选 Gaussian 均值。

更重要的是：仅仅计算两策略差异仍然不够，应该优先从教师真实完成成功闭环的轨迹中学习。

这样避免把历史教师在所有状态上的动作都当成正确监督。

构造两种轨迹监督：

\\[ \mathcal D^+ = \\{\text{历史教师成功、当前父策略失败的教师轨迹}\\}, \\]

\\[ \mathcal D^0 = \\{\text{当前父策略成功的父策略轨迹}\\}. \\]

在 \\(\mathcal D^+\\) 上学习恢复历史教师的动作行为，在 \\(\mathcal D^0\\) 上约束残差尽量保持零输出。

一个基本目标是：

\\[ \boxed{ L\_{\mathrm{OVR}} = \mathbb E\_{\mathcal D^+} D\left(\pi^{T}\_{\mathrm{exec}},\pi^{R}\_{\mathrm{exec}}\right) + \lambda \mathbb E\_{\mathcal D^0} D\left(\pi^{P}\_{\mathrm{exec}},\pi^{R}\_{\mathrm{exec}}\right) } \\]

其中 \\(D\\) 可以采用执行分布 KL，并针对夹爪开合单独使用分类一致性损失。

这与 ZR-v3 使用 KL 的意义不同：

- ZR-v3：只限制当前动作不要偏离父策略太远。
- OVR：使残差接近一个已真实完成该任务的历史策略，并尽可能保留父策略已完成成功的行为。

前者没有修正方向来源，后者具有明确的行为来源。

但教师成功并不证明它在所经每个状态下的单步动作都是最优的。因此仍需要独立闭环检验蒸馏效果。

### 4. 具体残差网络

对于当前阶段的时序特征：

\\[ z_k=T_k(H)\_{\mathrm{last}}\in\mathbb R^{512}, \\]

建立旧任务专属低秩分支：

\\[ R\_{k,j}(z)=U\_{k,j}V\_{k,j}z. \\]

首先保留 rank 8，不再增加全局成功投影，也不需要第二份冻结 \\(T_0\\)。

对连续运动维度，在执行动作均值层面进行残差修正：

\\[ \mu\_{1:6}^{R} = \operatorname{clip} \left( \mu\_{1:6}^{P} + g_j(e)R\_{k,j}^{motion}(z_k), -1,1 \right). \\]

夹爪单独训练执行类别，使用成功教师轨迹中的真实执行命令作为目标，绕过饱和的 `tanh` 预激活路径。

如果教师和父策略的动作尺度或执行模式存在显著差异，应在训练阶段明确蒸馏所选执行分布，并独立检验其复现能力；不能在看到闭环成绩后临时增加标准差修正。

每个阶段建立新残差，不反复继承此前已经可能失配的旧 UV。

因此：

\\[ R\_{7,6},\ R\_{8,6},\ R\_{9,6} \\]

分别适配阶段7、8、9的公共特征，而不是要求一个永久冻结分支适配所有后续表示。

## 四、这套方法如何避免再次破坏正确行为？

之前 SAZR 和 CZR 的一个教训是：静态特征投影或距离保护不能可靠保证未见状态的行为保持。

所以 OVR 不再试图仅靠几何规则决定每一步是否修改动作。

第一版采用任务—阶段级启用机制，不训练新的逐时间步错误判断器。

完成阶段 \\(k\\) 的 Coreset＋IFA 公共训练

新任务 \\(j=k\\)

原父策略直接执行，不增加残差

旧任务 \\(j\<escape><\</escape>k\\)

检查是否存在更强历史教师

真实闭环验证教师优势 → 学习历史能力残差

独立比较残差策略与当前父策略

未通过：精确回退父策略

通过：启用旧任务残差

这种设计与 SAZR 的闭环验收相比，增加了一项此前缺失的前提：

先证实存在更强的控制行为来源，再训练候选残差。

此前 SAZR 的七个失败初态没有被救援，原因之一是残差仅从离线示范学习微调，没有新的恢复行为监督。

OVR 可以直接从历史教师的实际成功轨迹中获得这类监督，而不需要假设专家演示在父策略偏离后的状态仍然适用。

独立验收时，记录：

\\[ FS=\\#(\text{父失败，残差成功}), \\]

\\[ SF=\\#(\text{父成功，残差失败}). \\]

仅当预先登记的成功净增益条件通过，才允许部署；例如探索阶段要求 \\(FS\ge2\\) 且 \\(SF\le1\\)。

这并不保证其他未见初态上的成功率，但能够阻止没有观察到实际改善的残差默认介入。

## 五、先做最有希望的低成本原型：OBJECT seed42，阶段9，Task 6

我建议不再从 Task 6 刚学完时开始测试残差。

以前的多次负结果都说明，刚完成行为克隆的父策略本身已经相当强，额外校准反而容易破坏其动作。

应该把第一轮实验放在遗忘最明显、且存在已知高性能历史教师的位置：

OBJECT seed42 · Task 6

当前阶段9父策略历史成功率

# 10%

阶段7历史教师成功率

# 80%

上述是已有20初态的历史结果，不是 OVR 的预测成绩。

### 第一关：历史教师的优势能否在独立状态上复现？

加载两个已有 checkpoint，使用独立开发初态进行成对闭环。

双方使用同一初态及按轨迹、时间固定的动作采样噪声，分别保存完整成功记录。

如果历史教师在开发状态上并不优于当前父策略，那么停止，不花时间蒸馏。

不能因为曾在正式0–19号初态上观察到80%对10%的差距，就直接宣布历史教师在未来初态上具有70个百分点优势。

### 第二关：能否将历史教师压缩成小型残差？

只使用开发数据中的教师成功轨迹训练残差，同时加入父策略成功轨迹的保持监督。

不需要重新训练公共策略。

训练完成后，检查在未参与残差训练的教师成功轨迹上，动作分布是否能够被准确复现。

这只是功能验收，不能用动作分布拟合通过替代闭环验收。

### 第三关：蒸馏后的残差能否真正恢复成功率？

在另一批完全独立的初态上，比较：

| 策略           | 用途           |
| ------------ | ------------ |
| 当前阶段9 RA＋IFA | 唯一主基线        |
| 历史阶段7完整教师    | 历史能力可恢复性上界参照 |
| 阶段9 RA＋OVR   | 检验是否成功迁移历史能力 |

如果历史教师有优势，但 OVR 没有优势，说明问题出在能力蒸馏或当前表示的可表达性，而不是缺乏有益历史行为。

如果历史教师也没有优势，应停止该任务的历史迁移，避免继续将过去的成功误认为当前可恢复能力。

正式测试仍使用原来每单元20次的 LIBERO 闭环协议，不能将开发集和正式集结果混合计算。

实际开始前，需要核对可用初态数量，并将教师筛选、残差训练、独立验收和正式测试分区冻结。若没有足够独立初态，就必须重新定义数据协议；此前已经用于方案设计的初态不能再冒充完全独立确认集。

## 六、如何扩展到完整持续学习？

首个原型通过后，才将该机制应用于 Task 6–9。

各阶段的处理如下：

| 当前训练阶段 | OVR 可修复的历史任务 | 当前新任务      |
| ------ | ------------ | ---------- |
| Task 6 | 无            | Task 6保持原样 |
| Task 7 | Task 6       | Task 7保持原样 |
| Task 8 | Task 6、7     | Task 8保持原样 |
| Task 9 | Task 6、7、8   | Task 9保持原样 |

每个旧任务的教师独立选择、残差独立训练、启用条件独立判断。

尤其要允许一种情况：

如果当前公共策略在某个旧任务上表现优于全部历史教师，就不建立该任务的残差。

这样不会为了“必须用上模块”而人为压制正向迁移。

对于原始 AUC 定义，Task 6 在阶段9的成功率若提高 \\(x\\) 个百分点，且其他单元不变，对整体 AUC 的贡献为：

\\[ \Delta AUC=\frac{x}{16}. \\]

例如理论上将 seed42 的阶段9 Task 6 从10%恢复到70%，这一单元就能增加：

\\[ \frac{60}{16}=3.75 \\]

个百分点 AUC。

这是指标计算关系，不是预测该残差能够实现60个百分点恢复。

这也说明为什么应优先解决严重旧任务遗忘，而不是在已经达到95%甚至100%的新任务上做风险较大的动作微调。

## 七、协议公平性与科学风险

OVR 可以保持原公共训练过程、原 Coreset Buffer、原任务顺序及正式评估协议，但如果利用新的教师闭环轨迹进行残差训练，它便增加了环境交互和成功标签监督。

这不能再被描述成与原 MLR＋IFA 完全等数据、等计算预算的纯离线持续模仿学习。

因此，后续论文比较至少需要明确报告新增教师 rollout 数、成功轨迹样本数、历史 checkpoint 使用、残差参数量和推理耗时；还需要与同等交互预算下的普通蒸馏或策略选择方法进行比较。

此外，历史完整教师直接进行任务级切换，也是一个必须包含的对照。只有当轻量 OVR 能在明显更低的部署成本下接近教师性能，或者实现额外的跨任务保持优势时，才能证明残差迁移有独立贡献。

### 创新性判断

单独的历史教师选择、策略蒸馏和低秩残差都不是新颖思想。

可能具有研究价值的是：

在持续潜在回放的每个阶段，使用实际闭环结果识别历史任务已经获得却被当前共享模型遗忘的能力，再通过任务零响应、当前阶段适配的轻量残差进行选择性能力恢复。

这比过去通过 NLL、动作距离或局部错误样本推断修正方向，更直接地连接了实际机器人成功行为。

但它的创新性和有效性仍需要消融与多 seed 证据支持。

## 最终建议

我建议改变下一轮的实验目标：

不要再证明残差可以纠正少数专家标签不一致的夹爪窗口，而要证明残差可以恢复历史模型曾经拥有、当前模型已经丢失的完整任务执行能力。

理由是现有数据已经显示：

- 夹爪单步标签错误很少，泛化修复又不稳定。
- 局部错误检索没有找到能够同时保持零损害的跨演示纠错区域。
- 三个 seed 的 Task 6 都存在明显的历史成功率下降。
- 完整历史模型和其他 Coreset 策略中，实际存在当前模型未能完成的成功轨迹。

所以最值得优先验证的不是 ZR-v4 的新门控或新损失，而是“历史成功策略 → 当前低秩残差”的能力迁移是否可行。
