# DEBR 稿件内容评阅

评阅日期：2026-11-07。来源：用户提供的 DEBR_Complete_Manuscript.docx。原稿未修改。

## 总体判断

论文已有扎实的方法主体和可组织成完整论证的实验，适合进入实质性修改阶段。当前优先级是比较口径、贡献定位和复现信息，而不是继续堆叠公式或扩大实验。

最值得突出的主线是：专家示范监督与策略成功执行历史提供不同的行为参考；成功历史约束并非每次都改善新任务学习，因此从同一完整训练状态比较基础候选与保持候选，选择性地提交更新。Q→S 对照、等优化器预算对照、门控记录和阶段任务图，能够围绕这条主线形成连贯证据。

## 已核验的优点

- 方法明确区分混合分布拟合与实际执行高斯分量，行为参考、路由、支持度和固定槽位分母有具体定义。
- 门控比较恢复完整状态，避免把不同起点的两条路径当作同状态比较；推理阶段无需门控和缓存，部署代价交代清楚。
- 等预算对照把被放弃候选的 optimizer 调用计入，并说明优化器预算不等于全部计算和环境交互成本。
- 对 Q 在 OBJECT 上的取舍，以及 GOAL λ=0.2 的低 NBT 与低 FWT，解释比较克制，没有把所有指标写成单调改善。
- 对照已验收图表数据逐 seed 复算，表2的 Q、表3等预算 C/S、表4三个 λ 的 FWT/NBT/AUC 均值及样本标准差，与稿件所列数值在显示精度下相符。表1中的 S 和表2中的 S 采用相同结果。未据此声称历史 RA、ALIGN、旧 C 及原始复现的所有数字均已独立复算。
- 两张嵌入图均已查看：保留了负差值，门控接受和拒绝没有被写成闭环成功概率。

## 必须优先修改

### 1. 表1须同时交代论文报告基线与本地复现基线

第4.2节已经说明 Sequential 至 TAIL 引用原论文、MLR+IFA 使用本地复现；问题是表中缺少 MLR+IFA 原论文行，导致比较不完整。原论文 Table 1（印刷页6745）报告：

|套件|MLR+IFA 原论文 FWT|NBT|AUC|
|---|---:|---:|---:|
|OBJECT|84.6±1.9|11.4±5.6|79.4±1.5|
|GOAL|80.0±2.5|6.9±0.9|77.2±1.8|

稿件本地复现 OBJECT FWT 为66.7，而 DEBR为80.4。与原论文84.6相比，DEBR不再是最高 OBJECT FWT。因此第4.3节“最高FWT”只能针对当前被列出的行，不能作为完整公开基线比较结论。

建议区分“reported”和“reproduced”，或把公开文献结果与同协议本地对照分成两个区块。解释复现协议与文献协议的可比范围，并以同协议对照支撑方法收益。加入原论文行后，DEBR的两个套件AUC均值仍较高；主线可以成立，无需依赖不完整的最高值表述。

### 2. 把创新层次与证据对应起来

当前介绍“两大模块”，实验却依次加入 RA、ALIGN、执行监督、支持加权保持和门控。应明确哪些是沿用组件、哪些是时间对齐修正、哪些是新机制，避免读者把基础修正与提出的新算法混为一谈。

现有 Q→S 对照支持加入门控后的完整训练路径效果；它不等于逐个条件的独立消融，也不能单独证明 q 加权优于均匀加权。C→Q 同时增加成功历史、行为参考和支持加权，只能检验这一组合。无需为此次评阅新增实验，先把贡献句写到证据实际支持的层级。

标题和贡献列表可突出“成功执行历史”和“候选更新选择”。当前三条贡献存在重复；“提出框架—设计模块—做实验”应改为清楚的问题、方法区别与关键发现。

### 3. 补足正式论文结构与引用

当前文件没有摘要、关键词和独立结论节，参考文献仅1条。CRIL、PolyTask、M2Distill、HReDiff、BUDS、TAIL、IsCiL 等均需要对应原始来源。相关工作不宜把一整类模块扩展方法概括为测试时都依赖任务标识；逐方法限定结论并核对原文。

引言前两段通用背景可压缩，尽早进入“示范上的预测保持与自主执行行为保持不是同一约束”的具体缺口。第1节和第2节中关于双经验互补的叙述可减少重复。

### 4. 交代历史配置与硬件来源

λ敏感性使用历史0.1与新增0.05/0.2，存在硬件迁移；部分历史累积配置也不是同一次完全受控的运行。第4.1节或附录应简明列出配置、硬件、种子、采集预算和优化器预算，避免把所有相邻行差值都表述为唯一组件的严格因果效果。

默认0.1在两个套件的所测三档中AUC均值最高，可以报告为观察结果；不能由此推出全局最优、统计显著或广泛不敏感。保留开发集反复使用和预训练来源未完全闭合的研究范围说明；无需在每段重复。

## 复现与图表的具体修改点

1. 补一个完整超参数表：执行监督与路由的系数、保持路由系数、margin、历史长度、GMM分量数、warmup、尺度计算/冻结方式及实际评估初始化与噪声设置。当前4.1节没有覆盖方法中所有自由量。
2. 算法1“没有旧成功历史时直接优化基础目标”的分支条件，与检查到的生产代码存在差异：代码按 stage>6 进入双候选，而不是按成功缓存是否非空决定。因此应准确写首个增量阶段与后续阶段，并说明空槽贡献为零。该点是算法描述修订，不建议修改已完成实验。
3. 图1横纵轴写 Relative Δ，但正文未给出归一化公式。绘图来源使用 200(Q−C)/(|Q|+|C|)，两值皆零时取零；symlog线性区阈值0.01%。应在图注或附录明示。左下区域仍可能因BC条件而拒绝，也值得用一句话解释。
4. 图2四个面板只写OBJECT/GOAL，读者须翻图注才能辨别两列。直接在列标题标注 DEBR−matched-budget C 与 DEBR−Q，更适合独立阅读。
5. 在方法开头增加框架图：示范记忆与成功历史记忆→两类损失→同状态双候选→三个接受条件→提交状态。当前两图都是结果分析图，未帮助读者建立方法整体结构。
6. “专家示范未能覆盖的自主执行状态”宜改成“策略自身访问的成功执行历史”，除非另有直接覆盖分析；已有数据支持经验来源不同，但未量化全部缓存相对于专家分布的覆盖边界。
