# 可视化选择与数据准备建议

2026-11-06。用户询问是否需要附件风格图像，以及应使用哪些数据。本次仅核对论文、已接受的本地结果和记录结构，未绘制正式实验图、提取特征、运行模型、启动环境或追加实验。数据来源和只读检查见 READINESS.json / audit_sources.py。所有已有接受记录保持不变。

## 建议顺序

1. 主结果：OBJECT/GOAL × C/Q/S 的阶段成功率曲线；任务×阶段热图或 S−Q、S−C 差值热图。
2. 机制：S 内部同状态 C/Q 候选的三条件取舍与接受/拒绝分布。
3. 超参数：两个套件三档 λ 的 AUC、最终旧任务、最终新任务，保留三个 seed 点及均值。
4. 补充：固定共同输入上的策略输出漂移、可训练 hidden 的漂移；UMAP/t-SNE 仅作辅助解释。

这套顺序能回答“表现如何、差异在哪、方法如何作出选择、参数如何影响取舍”。不建议为了视觉复杂度优先新增二维散点图。

## 立即可画的图

### 阶段曲线和热图

以每个 seed、每个阶段、每个任务的20个正式初态0–19计算成功率；先在 seed 内求值，再汇总三个 seed。固定矩阵 R[s,t]，s,t∈{6,7,8,9}、t≤s。未学任务留空/灰色，不填0。颜色范围0–100统一；差值图以0为中心且对称范围。只有4个增量阶段，不能照搬10/40任务的完整形状，也不能把训练epoch当正式评估横坐标。

曲线可包括已见任务平均、新任务对角成绩、旧任务平均；旧任务曲线在首阶段不定义。已见平均的分母随阶段增加，需配合各任务曲线/热图，不能把它直接当固定旧任务的遗忘曲线。误差条优先三个seed原始点+均值，或明确标注样本SD；不把跨阶段重复初态当独立样本计算窄置信区间。

主比较建议标清 C_equal_optimizer（Task6 100、7–9 200轮）与 Q_100 / S_100；原C100若纳入必须另列，不能把两种C混为一条线。Q/S同接受更新数及采集次数，但S双候选成本更高；C_equal_optimizer/S匹配生产optimizer成本但方法和采集不同。

Q/S 与等预算C/S来源分别为 execution/20261031_full_q_vs_latest_s_two_suites/final_readonly_20261101_032229/PRIMARY_S_COMPARISON.json、execution/20261030_equal_optimizer_budget_cs_two_suites/final_readonly_20261031_065009/PRIMARY_S_COMPARISON.json。组合时按 suite/seed/stage/task/initial_index 与初态、noise哈希复核，已有S只出现一次。

三λ图使用 cross_suite_comparison_20261104/MEANS.csv、PER_SEED.csv、FINAL_TASKS.csv。建议两个套件分面，三档0.05/0.1/0.2作离散点或log2间隔，显示每个seed。GOAL0.2旧任务略升而新任务下降，OBJECT0.2最早Task6明显下降；单独画最终总分会掩盖这些差异。保留历史0.1跨硬件和开发评估集复用限制。

### 门控与梯度

GATES.jsonl 或最终 light 下 GATES_stage7/8/9.jsonl 保存 stage、epoch、batch、start/end_step、C/Q的 bc_new、exec_new、retain_support、retain_by_task、checks、accepted。

建议按每个run及阶段计算 ΔBC=Q.bc_new−C.bc_new，ΔExec=Q.exec_new−C.exec_new，ΔRetain=Q.retain_support−C.retain_support。用 ΔExec 横轴、ΔRetain 纵轴，颜色区分接受/拒绝，并另面板交代 ΔBC 条件；三条件不能缩成只看两个轴。可用密度图避免大量重叠；跨阶段尺度差异宜分面或明确统一归一化，保留原值，不任意截掉反例。拒绝条件可能同时出现，按组合计数或注明占比不互斥。

这是真实同起点、同batch块的局部候选比较，优于用完整C/Q训练路径冒充共同状态。接受Q位于有利区域是门控定义本身，不是独立性能证据；不能把接受率称作闭环成功率。该图的价值在于显示候选冲突频率、改变量分布和三条件各自筛掉哪些候选，仍需正式outcomes支持最终收益。

GRADIENTS_S.json/GRADIENTS_Q.json提供保留项与BC/执行误差的梯度余弦和范数，但只是稀疏指定epoch诊断。画真实采样点，不能插值冒充全程测量；不能仅凭梯度同向断言闭环改善。MEMORY_* / STAGE_* 中成功数与q为训练支持度，可画任务权重，但不是正式成功率。

## 离线表征分析若要做，使用什么数据

1. 固定共同分析输入：优先现有共同RA/示范feature窗口，按task/demo/window或时间索引绑定SHA；各任务数量平衡、各轨迹限额，选择规则先固定，不按结果筛选好看的轨迹。已有20–29训练采集缓存可作另一种训练内分析；若使用各方法缓存的并集，所有模型都必须作用于同一并集并标明来源。分别画各自成功缓存会混入访问状态与成功过滤差异。
2. 模型：每个方法、seed、阶段6–9的已接受CP，按SHA绑定；仅eval/no_grad前向，不训练、不增加rollout。当前只核到了已接受CP的审计记录，尚未远程确认资产当前可读；实施前须核可用性。
3. 可训练特征：实现中 policy.temporal_encode(x)[:,-1] 是策略头输入，适合明确命名为decoder hidden；若要完全复现论文 g(T_k)，还须核实际IFA forward层及聚合定义，不能默认两者相同。每个点是一段固定历史窗口对应的表示，不是一个成功率数值。
4. 输出层更贴近本方法：记录混合头的均值、尺度、路由分布及确定性选中动作均值；用与保持项一致的归一化动作/路由差异，或预先定义的新度量，衡量旧任务从刚学完CP到后续CP的变化。不要把随机采样动作的差异混入策略变化。
5. 冻结前端：相同输入、相同冻结权重下，语言/视觉编码输出不会因后续优化改变。换输入后看到的差异是数据分布变化；不能按图2直接做语言/双相机三段堆叠并解释成我们减小了编码器漂移。不同向量空间的漂移值也不能无定义地相加。
6. 二维投影：同一输入、层、归一化、采样数量与绘图随机种子；比较面板使用联合拟合的一套投影或共同参考映射，不分别拟合后直接比较簇的位置与距离。三个seed分面/补充展示，不选最漂亮的seed；固定参数，不按论文叙事调图。先在原始高维空间计算逐样本漂移，再用UMAP辅助展示，不能用二维距离替代定量漂移。

原空间hidden漂移示例：D_{s,t}=mean_x[1−cos(h_s(x),h_t(x))]，同一个旧任务输入x，h_t为刚学完任务t的模型。输出分布距离应同时报告，因为hidden变化本身未必等于行为退化。

UMAP随机性与复现设置参见官方文档 https://umap-learn.readthedocs.io/en/latest/reproducibility.html 。二维表示不是闭环收益证明；不以簇更紧/更分离单独推导更少遗忘。不会因这次绘图提议新增训练、补采、重评或独立holdout的声明。
