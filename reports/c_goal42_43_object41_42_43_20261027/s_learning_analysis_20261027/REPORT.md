# S为何可能损害新任务学习：已有三seed证据分析

本次仅读取已验收结果、梯度范数、epoch标量、缓存元数据及冻结实现。0模型前向、0优化器调用、0环境回合、0远程调用。不启动或恢复任何实验。所有数值来源SHA及复算在AUDIT.json。

## 先界定实际受损范围

S并非普遍降低所有新任务学习。GOAL Task8刚学完时，三个seed的C→S为90→80、85→60、80→70，平均85→70，均下降；这些是在Task8对角单元的成绩，不能归为后续Task9遗忘。GOAL Task9的C→S为90→95、90→75、55→95，均值反而提高10pp。OBJECT Task9为100→55、100→95、95→100，平均98.3333→83.3333，损失主要来自seed41。

因此问题是特定任务和训练路径下的学习—保持取舍，而不是S一律限制新任务。Task6无保持时的完整模型相等证据、输入和预算绑定、父训练状态不受采集影响及自身关保持=原C更新准入均通过，未发现重训、样本替换或dropout流被额外采集扰动的证据。

## 1. 保持目标没有“为新任务让路”的条件：最直接的设计解释

C学习主干为BC+0.1IFA+0.1专家辅助。S额外加0.1×(执行分量W2距离+0.1保持margin路由)。距离同时约束均值和标准差到任务获得时教师的执行高斯；路由让与该教师分布最近的学生分量获更高logit。它没有新任务损失上升时的减弱条件，没有允许专家纠错的门，也不判断偏离旧教师是否改善整个序列。

保持作用通过同一时序网络和GMM参数实现，没有独立参数空间或硬隔离保护。新任务要改变共享表示、均值、方差或logits时，旧行为约束可能缩小可用调整范围。这是从代码可推出的竞争可能性；没有保存梯度方向，不能把它升级为已观测的负梯度夹角或某一层冲突。

保持每个Task7–9主更新都执行4个额外旧任务锚，即使主batch没有合法旧样本也存在；C专家辅助则只作用于batch中合法旧样本。保持是持续施加的旧行为偏好，不随新任务学习困难调整。总槽位固定4、按4平均，不能说旧任务数增长令总保持权重线性增加；增长的是被约束行为的种类，单个任务的期望槽位份额反而下降。

## 2. 不能用“保持梯度过大压倒BC”概括已有结果

六个run共72个稀疏取点（各旧阶段epoch0/9/49/99的首个合法旧batch）中，已加权保持回归与保持路由的梯度范数之和除以混合BC梯度范数，中位数0.01643%、最大0.46028%。这个和只是合并保持梯度范数的上界，不能推断方向；BC也包含新旧样本，并非单独新任务梯度。

这些数值不支持已测点上保持项在全参数范数上压倒BC。相对很小的持续偏好仍可能改变敏感参数方向、argmax边界和长期训练路径，但现有数据没有新任务单独梯度、夹角、分层范数或Adam实际步方向，不能确认上述具体机制。

另一方面，Stage9全epoch平均加权保持辅助的标量值是加权专家辅助的1.64–2.25倍，说明它不是数值上恒等于零的装饰项。该比值比较的是两个不同目标、不同采样分布及尺度下的loss值，不等同梯度强度，更不等同物理损害。

## 3. 成功轨迹整体筛选，并不能保证每个被固定的决策值得保持

代码先为每条训练轨迹均匀reservoir采样12/13个时间窗口，再按整条轨迹最终成功决定是否保留。没有关键决策标签，也没有每步专家优劣或反事实贡献。一次成功可能包含可替代或低效动作；筛选本身无法区分必须保持的动作与可让新任务学习覆盖的细节。

缓存保存的是采样前最高logit分量的均值和标准差，不是成功那次实际采到的动作。因此成功标签不能保证该高斯分布的所有输出都有效；匹配该分布也不保证复现成功轨迹。保持方差及路由会进一步限制旧分布周围的调整，但现有发布标量不足以独立判断均值、方差还是路由导致新任务下降。

保持路由的目标是最接近旧教师的分量，专家路由的目标是最接近示范动作的分量；两者作用状态分布不同，并通过共享参数发生耦合，不能直接声称同一窗口已有相互矛盾标签。尤其OBJECT41 Stage9的4个梯度取点上保持路由梯度均为0，不能说55%的新任务成绩已被证明由路由项主导；全epoch路由平均非零又说明不能彻底排除其作用。

## 4. 固定任务均衡权重与缓存可信度脱钩：有直接覆盖证据的缺口

OBJECT seed41/42的Task6各10次采集中仅1条成功，缓存仅13窗口；seed43是5条成功、63窗口。前两seed Task7–9仍按旧任务均衡抽取；到了Task9，该13窗口任务与128窗口任务具有相同的期望任务权重。任务内有放回抽样会反复使用少数相关状态，Task7的90800个槽位全部来自这13窗口，期望每窗口约6984.6次。

因此有效覆盖少不意味着保持影响自动减弱，窄分布可以被长期赋予完整任务份额。它既可能保护真实成功行为，也可能将个别轨迹特征固定成过强的通用偏好。不过OBJECT41和42同样13窗口，Task9分别下降45和5pp，证明缓存大小单一变量不能解释全部结果；任务难度、后续教师和参数路径仍不同。

当前每更新4个槽位，三旧任务时平均每任务约1.33个样本，单步估计可能受抽样变化影响。没有保存逐步方差，不能宣称已实测梯度噪声过高。

## 5. 全序列累积改变了新任务的起点，不能把末期损失归于最后一个阶段

C与S各自从官方初始化完整训练，Stage7之后参数即可能分化。S在各任务获得时用自己的模型建立固定缓存；后续同时继承此前的参数变化和此前的行为参考。GOAL Task8三seed对角下降说明受损在学习Task8时已出现，并非只在Task9发生；但没有共同Stage8检查点分叉，本轮无法分离“进入Task9之前的模型不同”和“Task9阶段保持项本身”的贡献。

固定教师减少参考随遗忘漂移，却也阻止重新评价较早行为是否仍值得保存。它是持续的软牵引，不是冻结参数；不存在已证明的不可调整硬锁。

## 离线证据能排除哪些过度解释

旧专家窗口与闭环不单调：OBJECT42最终Task6，C专家误差0.002858、S0.008895，闭环却C35%、S65%。旧示范误差不是判断整个方法是否更好、是否伤害新任务的充分代理。

OBJECT41末epoch的混合BC平均C约-33.86655、S约-33.86378，数值相近，Task9闭环却100%/55%。这只能说明混合训练NLL不能解释该闭环差距；不能据此宣布新任务示范拟合同样好，因为日志未按任务拆分。负NLL在连续分布中允许出现，不是日志错误。

现有最终专家诊断只覆盖旧合法窗口；没有新Task9完整独立诊断，也没有失败前共同观测历史的反事实动作干预。因此不能定位某次抓取、接触、释放、夹爪或方差错误为已证实根因，也不应提出“调小某个系数必然解决”的保证。

## 证据支持的结论与设计方向

最有依据的解释是：S把“旧成功轨迹上曾执行过的高斯分布”作为持续且固定的参考，在共享模型中改变了优化偏好；它能改善部分旧任务，但没有判断哪些细节可以为新任务让路。窄缓存仍获固定任务份额、整轨迹成功替代每步动作质量、固定历史参考和全序列路径依赖，都是明确的设计缺口或与结果相容的机制。

已证实的是部分新任务的闭环下降和上述实现事实；未证实的是具体负梯度夹角、某个GMM误选或某次物理操作的唯一因果。更合理的后续设计讨论应分别考虑保护对象的必要性、缓存覆盖与权重的关系、对新任务学习的约束检查以及阶段起点控制，而不是仅凭loss数值再调大/调小全局lambda。本轮只做上述分析，不增加实验、模型调用或扫描。
