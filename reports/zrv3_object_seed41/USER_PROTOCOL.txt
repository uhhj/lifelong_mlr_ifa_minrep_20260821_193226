1. 公共策略保持原样
对于缓存中的8步历史 \(H\)，父模型给出：
\[
z=T_k(H)_{\mathrm{last}},
\]

\[
\{b_m,\sigma_m,\ell_m\}_{m=1}^{5}
=G_k(z).
\]

其中 \(b_m\) 是均值前激活，\(\sigma_m\) 是标准差，\(\ell_m\) 是混合分量 logit。

父策略执行时选择：
\[
\boxed{m^*(H)=\arg\max_m\ell_m(H)}
\]

并从该分量采样：
\[
a=\tanh(b_{m^*})+\sigma_{m^*}\odot\epsilon,
\qquad \epsilon\sim\mathcal N(0,I).
\]

这对应当前原生推理代码中 selected_dist() 的实际行为。实际模型代码
2. 残差仍使用冻结特征与双向指令门
定义：
\[
q(H)=T_0(H)_{\mathrm{last}},
\]

\[
r_j(H)=U_jV_jq(H).
\]

用既有双向门 \(h_j(e)\) 合成：
\[
d(H,e)=0.1\tanh\left(\sum_{j=6}^{k}h_j(e)r_j(H)\right).
\]

对已知的任务指令，仍然要求：
\[
h_j(e_i)\approx \mathbf1[j=i].
\]

新模块不训练语言门，也不根据任务损失或回放样本价值来打开或关闭某个分支。
3. 只修正实际执行的 GMM 分量
这是第一处实质修改。

ZR-v2 对五个分量都加入相同的均值前激活修正：
\[
\mu'_m=\tanh(b_m+d).
\]

但执行时只采样 \(m^*\)。因此，ZR-v3 改为：
\[
\tilde\mu_{m^*}=\tanh(b_{m^*}+d),
\]

\[
\tilde\mu_m=\tanh(b_m),\quad m\ne m^*.
\]

\[
\boxed{\sigma'_m=\sigma_m,\qquad \ell'_m=\ell_m.}
\]

这样，残差的输出与机器人实际采样的那个动作模式一一对应。它不能改变分量选择，也不会为了提高其他未执行分量的专家动作似然而移动那些分量。
三、重新定义训练目标：优化实际执行策略，而非整个混合分布
ZR-v2 的训练目标
当前代码使用：
loss = -out["gmm"].log_prob(actions[:, -1]).mean()



对应：
\[
L_{\mathrm{v2}}
=
-\log\left(
\sum_m\pi_m
\mathcal N(a^*;\mu'_m,\sigma_m)
\right).
\]

这是合法的 GMM 行为克隆目标，但不等于评估时实际选中分量的负对数似然。

整个混合分布的似然可以因为某个未被执行的分量更接近专家动作而提高，而真正执行的 \(m^*\) 分量未必因此更接近专家。

这正是现有代码能确认、值得优先处理的训练—推理差异；报告尚未测量它对失败的具体贡献大小。
ZR-v3 的训练目标
只计算实际执行分量的专家动作似然：
\[
\boxed{
L_{\mathrm{exec}}
=
-\frac1B\sum_{n=1}^{B}
\log\mathcal N
\left(
a_n^*;
\mu'_{m_n^*}(H_n),
\sigma_{m_n^*}(H_n)
\right)
}
\]

其中 \(m_n^*\) 由冻结父策略的 logits 确定。

这意味着训练与执行使用的是同一个动作分布：
训练目标与执行分布对齐；不改变父模型原有的五分量选择规则。
这项修正具有明确含义：不要求模型学习任何额外评分，也不生成伪专家动作；监督仍然只来自真实示范中的末端动作。

它仍是离线行为克隆，不能因此保证闭环成功率提高。机器人偏离专家轨迹后，动作误差和环境反馈仍可能放大。
四、增加一个真正约束自身残差的机制：父策略动作分布信任域
仅仅更换训练损失还不够。ZR-v2 已经证明，修正幅度不大，也可能伴随成功率下降。

因此，ZR-v3 的第二处实质修改是：对每个输入，直接限制残差执行分布相对于当前父策略执行分布的偏离。

这不是根据预测损失、遗忘程度或不确定性估计样本的重要性，而是对实际动作概率分布施加一个精确定义的约束。
1. 计算父策略与候选残差的差异
父策略选中分量的均值：
\[
\mu_0=\tanh(b_{m^*}).
\]

候选残差修正后的均值：
\[
\tilde\mu=\tanh(b_{m^*}+d).
\]

定义：
\[
u=\tilde\mu-\mu_0.
\]

由于前后标准差保持不变，两个选中 Gaussian 之间的 KL 散度有闭式表达：
\[
\boxed{
D_{\mathrm{KL}}
=
\frac12
\sum_{j=1}^{7}
\frac{u_j^2}{\sigma_{m^*,j}^{2}}
}
\]

这里测量的是机器人实际执行的两个动作分布之间的差异，不是遗忘代理指标。
2. 对修正进行确定性投影
给定预先冻结的信任域预算 \(\varepsilon\)，设：
\[
\alpha
=
\min\left(
1,\sqrt{\frac{\varepsilon}{D_{\mathrm{KL}}}}
\right),
\]

当 \(D_{\mathrm{KL}}=0\) 时，定义 \(\alpha=1\)。

最终执行均值为：
\[
\boxed{
\mu_{\mathrm{v3}}=\mu_0+\alpha u.
}
\]

这保证在数值精度范围内：
\[
D_{\mathrm{KL}}
\left(
p_{\mathrm{v3}}^{\mathrm{exec}}
\Vert
p_{\mathrm{parent}}^{\mathrm{exec}}
\right)
\leq\varepsilon.
\]

第一版可以预先固定 \(\varepsilon=0.5\) nat，即标准差归一化后的总均值位移范数最多为1。这是待验证的工程设计值，不是报告已经证明有效的参数，也不能根据 seed41 的结果事后放宽。

这一机制与原来的0.1幅度界不同：即使同样修正0.02，在父策略非常确信的控制维度上，它可能是明显的分布变化；在标准差较大的维度上，影响则不同。

需要强调：信任域只能给出逐状态动作分布的偏离上界，不能保证整段机器人轨迹成功。 误差仍会沿闭环累积，有限信任域只是降低不必要的大幅动作改写的可能性。
五、ZR-v3 完整学习流程
继续采用 ZR-v2 的“公共训练与残差校准分离”，但残差训练、投影和部署全部使用新的执行一致性定义。
1. 读取任务 \(k\) 已训练完成的公共策略 \(C_k\)
   
   这是原 Coreset／RA＋IFA 的 epoch99 模型。冻结全部公共参数。
2. 构造本阶段双向零响应门
   
   沿用已验收 FP64 门矩阵，只使用当前及历史指令。
3. 建立／继承任务残差分支
   
   新任务分支零输出初始化；旧任务分支从本方法上一阶段暖启动。
4. 使用 \(D_k\cup B_{<k}\) 校准
   
   每条样本先由公共 GMM 确定真实执行分量，再计算修正、KL 投影和选中 Gaussian 的专家动作似然。
5. 保存校准后策略并评估
   
   使用与训练一致的选中分量、分布投影和采样逻辑；记录执行预算与结构约束。
6. 按原 Coreset 规则入库
   
   不改变缓存成员、任务配额、样本文件排序，也不通过校准损失重新选样。

训练代码应该怎样改变？
目前真正需要改动的主要是 reference_core.py 中的 corrected_gmm 逻辑，以及 zr2_exp/model.py 中的 decode()、NativeHead 和 update()。

新的核心逻辑可以写成如下伪代码：

# parent, T0、language gates 全部冻结
# base_mean_pre, scales, logits: 冻结父GMM输出

selected = logits.argmax(dim=-1)
rows = torch.arange(batch_size, device=logits.device)

base_mu = torch.tanh(base_mean_pre[rows, selected])
base_sigma = scales[rows, selected]

q = T0(history)                  # 冻结的512维表示
d = residual_bank(q, language)   # [B, 7]，保留梯度

proposal_mu = torch.tanh(
    base_mean_pre[rows, selected] + d
)

shift = proposal_mu - base_mu

# 使用真实动作分布的KL计算信任域
kl = 0.5 * ((shift / base_sigma) ** 2).sum(dim=-1)
alpha = torch.minimum(
    torch.ones_like(kl),
    torch.sqrt(epsilon / kl.clamp_min(1e-12))
)

executed_mu = base_mu + alpha[:, None] * shift

executed_dist = torch.distributions.Independent(
    torch.distributions.Normal(executed_mu, base_sigma),
    1
)

# 与机器人执行同一Gaussian的真实专家动作似然
loss = -executed_dist.log_prob(
    expert_actions[:, -1, :]
).mean()

loss.backward()  # 只更新当前有自身样本的残差分支




在真正实现中，应沿用现有训练时的任务归属梯度屏蔽、grad=None 语义、参数冻结与恢复机制。KL 计算及投影需要实测 FP32／FP64 误差，保证最终实际执行分布满足约束。

最重要的是训练和在线执行必须调用同一套校准函数。 如果训练用了投影，推理却直接采用原始残差，整个修正就失去意义。

六、我为什么没有同时修改冻结 \(T_0\)？
ZR-v2 的固定 \(T_0\) 可能存在表征失配：父策略已经在 Task 6–9 适配，而残差仍使用官方预训练阶段的时序特征。

但当前报告没有证明它造成了多少损失。如果现在同时把：
\[
q(H)=T_0(H)
\]

改成：
\[
q_k(H)=T_k(H),
\]

旧分支的输入会随任务阶段变化，现有暖启动也需要重新设计。

因此，我建议将其作为单独的第二步结构对照，而不是直接混进 ZR-v3 主实验。

如果执行一致性版本仍无稳定改善，再检验阶段冻结表示的版本。此时应明确比较重新初始化旧分支与重新校准旧分支，不能简单替换特征输入后默认旧 UV 仍有相同含义。

这样也有助于区分两种问题：
问题	对应实验修改
校准目标没有对齐真实执行	ZR-v3：选中分量损失＋动作分布信任域
冻结预训练特征难以表达当前动作误差	后续单独测试阶段适配后的冻结特征

为了知道新版本是否真修正了已观察到的缺口，最终应有以下对照：
方法	选中分量训练	信任域投影	用途
ZR-v2	否	否	复用已有负结果

应怎样判定结果？
我建议新版本的前瞻性筛选条件采用：
\[
\Delta AUC>0,\qquad
\Delta FWT\geq0,\qquad
\Delta OldFinal\geq0.
\]

同时逐任务报告初学成功率和最终成功率，NBT 保留原公式，但不单独用它作为否决条件。

这只适用于新实验在开始前冻结的推进规则，不能回头修改 ZR-v2 已经完成的停止判定。单 seed 通过后，再测试其他 seed，并至少要求多 seed 平均改善且多数 seed 为正。

验收还必须包含三个与先前不同的新增检查：训练与推理选中分量身份一致；每个真实缓存样本的执行分布 KL 满足冻结上界；关闭残差时能够准确恢复当前父策略的执行分布。旧零响应及输入哈希检查全部继续保留。
