# 三、E1新增模块及固定参数

## 1. 模块定义

E1采用：

> **旧缓存平均BC损失检查＋候选参数处的单次局部修正＋修正幅度限制＋一次复检。**

每10次基础更新检查一次。检查不通过时，不直接取消整步学习，而是尝试少量纠偏；纠偏无效，则撤销纠偏、保留原AdamW更新。

## 2. 首轮参数

| 参数 | 固定值 | 作用 |
|---|---:|---|
| 检查间隔 \(K\) | 10 | 每10次实际基础优化器更新检查一次 |
| 检查批次大小 \(B_A\) | 20 | 从合法旧缓存抽取20个有效输入窗口 |
| 相对容忍系数 \(\tau\) | \(10^{-4}\) | 避免对极小损失变化过度干预 |
| 数值比较系数 \(\tau_{\mathrm{num}}\) | \(10^{-6}\) | 判断修正是否可靠降低损失 |
| 修正幅度比例 \(\rho\) | 0.25 | 修正长度最多为原更新长度的25% |
| 梯度范数下限 | \(10^{-12}\) | 避免接近零的梯度导致不稳定除法 |
| 最大修正次数 | 1 | 不反复优化检查批次 |
| 最大复检次数 | 1 | 修正后仅检查一次 |
| 启用时间 | 增量阶段，且旧缓存非空 | 不改预训练，不额外创建历史记忆 |

**这组参数在整个OBJECT四阶段运行中保持固定。**不根据中途单任务结果、闭环成功率或触发率动态调节。

## 3. 检查数据的边界

检查批次来自**当时原框架允许访问的旧缓存**，不是另建一个数据集。

保留以下规则：

**不永久拆分缓存。**检查样本仍可在以后用于正常回放；它们是训练控制数据，不是独立测试集。

**不改变正常回放。**检查抽样使用独立随机数发生器，沿用原旧回放的抽样分布，不修改原训练batch或回放权重。

**不访问旧任务完整数据或未来任务数据。**磁盘上存在完整特征文件，不代表E1可以读取。

**同一次检查使用同一批样本。**更新前、候选更新后、修正后均使用批次 \(A\)；下一次检查再重新抽样。

旧缓存不足20个有效窗口时使用现有全部窗口；为空时跳过。若原增量流程初始缓存为空，第一阶段没有E1检查，第二阶段开始才可能触发，这是正常行为，不需要额外加入预训练任务样本。

# 四、一次E1更新的完整算法

## 1. 检查损失：沿用原BC，不换评价对象

本次核对的公开实现使用GMM策略头，其BC为专家动作的负对数似然，目标使用输入窗口对应的最后一个动作。E1应复用这个损失定义，不改成GMM均值的MSE，也不改成整段所有时间位置的平均误差。

设检查批次为 \(A\)，每个样本的原BC损失为 \(\ell_i\)，定义：

\[
L_A(\theta)=\frac1{|A|}\sum_{i\in A}\ell_i(\theta).
\]

容忍尺度使用：

\[
S_A=
\max\left(
1,\frac1{|A|}\sum_{i\in A}|\ell_i(\theta_0)|
\right),
\]

\[
\varepsilon_A=\tau S_A,\qquad
\xi_A=\tau_{\mathrm{num}}S_A.
\]

这里用绝对值构造正尺度，避免损失为负或样本间正负抵消时产生错误阈值。**该尺度只用于触发阈值，不改变原BC损失或修正梯度。**

## 2. 保存更新前状态并执行原更新

到检查时点时，抽取批次 \(A\)，保存当前可训练参数：

\[
\theta_0=\theta,
\]

计算更新前损失：

\[
L_0=L_A(\theta_0).
\]

随后完整执行原MLR＋IFA训练步骤，包括原反向传播、梯度裁剪和一次AdamW更新，得到：

\[
\theta_c=\theta_0+\Delta_0.
\]

再由参数差计算实际更新：

\[
\Delta_0=\theta_c-\theta_0.
\]

**\(\Delta_0\)是AdamW真正执行的位移，不能用原始梯度乘学习率代替。**

## 3. 判断是否触发修正

对同一批次计算：

\[
L_c=L_A(\theta_c),
\qquad
q=L_c-L_0.
\]

若：

\[
q\le\varepsilon_A,
\]

直接接受原候选参数 \(\theta_c\)。

若：

\[
q>\varepsilon_A,
\]

计算超标量：

\[
v=q-\varepsilon_A>0,
\]

尝试一次修正。

注意，参考水平是**本次更新之前的损失**，不是旧任务刚学完时的历史损失。累计退化预算不属于E1。

## 4. 在候选参数处计算最小局部修正

计算旧检查损失梯度：

\[
g_A=\nabla_\theta L_A(\theta_c).
\]

对较小修正 \(r\)，采用局部近似：

\[
L_A(\theta_c+r)
\approx
L_A(\theta_c)+g_A^\top r.
\]

于是，未限幅的局部修正问题为：

\[
\min_r\frac12\|r\|_2^2,
\qquad
\text{使得 }v+g_A^\top r\le0.
\]

单约束条件下，其解为：

\[
r^*=-\frac{v}{\|g_A\|_2^2}g_A.
\]

实际执行时加入限幅，直接写成：

\[
\boxed{
r=
-\min\left(
\frac{v}{\|g_A\|_2},
\;\rho\|\Delta_0\|_2
\right)
\frac{g_A}{\|g_A\|_2}
}
\]

其中，范数在**全部原可训练参数组成的整体向量**上计算，不逐层各自分配25%的独立修正预算。

**\(r\)已经是参数位移，不再乘学习率，不再经过第二次AdamW。**

这只是局部线性近似下的最小修正。限幅后可能无法消除全部超标，也不保证对新任务性能影响最小。

## 5. 复检一次，接受或撤销修正

保存候选参数 \(\theta_c\)，临时应用：

\[
\theta_f=\theta_c+r,
\]

计算：

\[
L_f=L_A(\theta_f).
\]

固定接受规则如下：

| 条件 | 操作 |
|---|---|
| \(L_f\le L_c-\xi_A\)，且数值正常 | 接受修正，保留 \(\theta_f\) |
| 修正没有可靠降低旧检查损失 | 精确恢复 \(\theta_c\) |
| 梯度范数过小、原更新为零或修正数值异常 | 跳过修正，保留 \(\theta_c\) |

即便修正后仍有：

\[
L_f>L_0+\varepsilon_A,
\]

只要相对 \(L_c\) 有可靠改善，也接受这次有限修正，并记录“残余超标”。

**不反复修正，不撤销整次原更新，不额外检查新任务损失来否决更新。**这些都不是当前E1的组成部分。

# 五、代码接入与工程验收

## 1. 接入方式

新增一个E1辅助模块，在原训练步骤外增加：

\[
\text{更新前检查}
\rightarrow
\boxed{\text{原MLR＋IFA更新一次}}
\rightarrow
\text{候选检查}
\rightarrow
\text{必要时单次修正与复检}.
\]

原目标函数、优化器创建、正常采样、缓存更新和闭环评估代码不重写。

下面是控制流程伪代码，函数名称需要按现有项目接入：

```text
加载已有OBJECT预训练模型
初始化本次E1独立输出目录与合法初始缓存

依次执行原四个增量阶段：
    阶段内基础更新计数 t = 0

    对每个原训练batch：
        do_check =
            E1开启
            且旧缓存非空
            且下一次实际更新编号为10的倍数

        如果 do_check：
            A = 独立抽取旧检查batch
            theta0 = 保存可训练参数
            L0, sample_losses = 确定性BC检查(A)
            计算 epsilon_A 和 xi_A

        原MLR+IFA训练步骤执行一次
        # 包含原backward、grad clip和AdamW step

        如果优化器未实际更新：
            不执行E1修正
            按原数值处理流程继续

        t += 1

        如果不需要检查：
            继续下一batch

        theta_c = 当前参数
        Delta0 = theta_c - theta0
        Lc = 对同一A进行候选检查

        如果 Lc - L0 <= epsilon_A：
            保留theta_c，记录未触发
            继续下一batch

        v = Lc - L0 - epsilon_A
        g = 在theta_c处计算A上的平均BC梯度

        如果梯度或位移无效：
            保留theta_c，记录原因
            继续下一batch

        保存theta_c
        计算限幅修正r
        临时写入theta_c + r
        Lf = 对同一A复检一次

        如果Lf有限，且Lf <= Lc - xi_A：
            保留修正
        否则：
            精确恢复theta_c

        恢复所有临时运行状态
        保存E1日志

    按原规则保存检查点、更新缓存和执行闭环评估
```

检查计数基于**实际优化器更新**。如果原代码有梯度累积或混合精度溢出跳步，不能把每次前向都计为一次更新。

## 2. 确定性检查不能破坏原模型接口

核对的公开`BriefPolicy.forward`仅在`self.training`为真时返回分布和特征。因此，不能简单地整模型`eval()`后照常调用原损失接口。

检查函数需要：

**保留训练用的BC输出接口，临时关闭检查中的dropout等随机机制，保留GMM的原始似然计算，结束后恢复原状态。**

不能通过改用最大概率动作、采样动作或固定另一种方差来获得所谓“确定性损失”。GMM头存在训练／评估相关的方差分支，需要避免无意切换。

正常训练前向仍然使用原来的训练模式。E1检查不能改变归一化统计、动作历史队列或其他持久缓冲区。

## 3. 梯度、优化器和随机数隔离

**梯度隔离。**只在计算 \(g_A\) 时启用梯度，采用`torch.autograd.grad`取得检查梯度，不累积到正常训练的`.grad`中；其余检查使用无梯度前向。PyTorch明确区分模块评估模式与梯度记录模式，不能将二者混用。[PyTorch Docs](https://docs.pytorch.org/docs/2.13/generated/torch.autograd.grad.html)

**优化器隔离。**原AdamW每个基础步骤只推进一次。修正是额外参数位移，不更新AdamW的动量、二阶矩或计数，调度器也不额外推进。

**随机数隔离。**检查样本使用独立随机流；额外检查不得改变后续原训练的数据顺序和随机状态。

**数值处理。**检查损失、梯度和范数采用一致的FP32计算，正常训练精度保持原设置。若修正失败，恢复保存的候选参数，不依赖“加上修正再减去修正”来假定精确还原。

程序错误、形状不匹配或基础训练参数非有限值应停止并修复，不能一律捕获后当作普通“跳过修正”。

## 4. 开跑前只做小规模代码验收

这些是少量批次的工程测试，**不是重新运行一条基线训练实验**。

| 验收项 | 通过条件 |
|---|---|
| E1关闭 | 包装器不改变原更新结果 |
| 修正比例设为0 | 额外检查不改变参数、采样和模型状态 |
| 相同参数重复检查 | 同一批次损失在数值容差内一致 |
| 参数范围 | 只修改原可训练参数 |
| 更新计数 | 每个基础步骤最多执行一次AdamW更新 |
| 修正限幅 | \(\|r\|\le0.25\|\Delta_0\|\) |
| 修正撤销 | 恢复候选参数，而不是更新前参数 |
| 梯度隔离 | 下一步基础训练不残留检查梯度 |
| 保存加载 | 评估加载的是最终接受的参数 |
| 数据来源 | 所有检查样本都属于当时合法旧缓存 |

验收完成后冻结代码和参数，不开展额外的离线指标相关性实验，直接进入完整E1训练。

\mathrm{AUC}_{E1}-\mathrm{AUC}_{\mathrm{ref}}.
\]

若总体AUC提高，冻结`E1-OBJECT-v1`配置，补跑43、44；两个新增seed都从规定的预训练起点重新执行完整四阶段训练，不能只改变环境评估seed。

已有固定seed列表时沿用。若多个seed共用同一预训练模型，应报告为**固定预训练起点下的三次增量训练重复**。

如果改了E1算法或参数，就建立新版本，不能将不同版本的三个seed合并成一组结果。

# 七、日志、成本和最终判定

## 1. 保存两类结果

### 闭环主结果

保存每次执行的任务、阶段、检查点、环境初态编号及成功与否；由原汇总脚本得到总体指标。

| 方法／结果来源 | Seed数 | 总体AUC↑ | 总体NBT↓ | 总体FWT↑ |
|---|---:|---:|---:|---:|
| 已有MLR＋IFA参考 | 按已有记录 | 已有值 | 已有值 | 已有值 |
| E1-OBJECT-v1，seed 42 | 1 | 实测 | 实测 | 实测 |
| E1-OBJECT-v1，三seed | 3，后续有收益时补齐 | 均值±标准差 | 均值±标准差 | 均值±标准差 |

不在表中填写尚未提供或尚未运行的数值。

### E1机制日志

每次检查记录：

\[
L_0,\ L_c,\ L_f,\ q,\ \varepsilon_A,\ v,\
\|g_A\|,\ \|\Delta_0\|,\ \|r\|.
\]

同时保存阶段、epoch、更新编号、检查样本标识、是否触发、是否限幅、是否接受修正、残余超标和异常原因。

阶段汇总包括检查次数、触发率、接受率、限幅率和跳过原因。**这些指标用于解释训练行为，不作为模块有效性的替代证据。**

## 2. 成本统计不需要重跑基线

记录本次E1的训练墙钟时间、闭环评估时间、峰值显存，以及检查与修正部分的累计耗时。

已有可比硬件上的基线耗时，直接计算时间倍率；没有则只报告E1实测时间及内部额外开销，**不为了计算倍率重新跑基线**。

按不保留候选检查计算图的实现，一次未触发检查需要两次额外前向；触发后增加一次前向与反向，以及一次复检。检查频率为 \(1/10\)，实际成本取决于触发比例、检查batch和硬件，不能预先承诺固定减速倍率。

不复制冻结骨干；参数快照和梯度只保留在原可训练部分，检查结束后及时释放临时张量。

## 3. 统一判定规则

| 总体表现 | 本轮处理 |
|---|---|
| 总体AUC高于固定参考 | 作为单seed正向信号，进入三seed确认 |
| 总体AUC不高于参考 | 当前配置不判定为有总体收益 |
| NBT下降，但总体AUC下降 | 不因“遗忘更低”单独认定成功 |
| 检查损失下降，但总体闭环无改善 | 只能说明代理损失被改善 |
| 某些任务下降，但总体AUC提高 | 不单独否决，任务结果仅用于解释 |

首轮的正向差异只是继续投入计算的依据，不等于稳定提升。三seed完成后，报告全部seed、均值和标准差；只有已有对应seed基线时才报告配对差值，否则明确为与固定历史参考的比较。
