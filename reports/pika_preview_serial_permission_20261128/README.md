# B1 只读预览在 Pika 串口打开阶段退出

现场日志表明，旧设备节点上的临时授权解释了之前可以读、新节点不能读的差异。11 月 26 日 17:22:43，系统记录了一次针对 `/dev/ttyUSB0` 的 `setfacl` 操作，向现场账号授予读写权限。11 月 28 日 13:51:14–13:51:44 的上一轮通过 USB 串口取得了 532 帧带夹爪反馈的预测记录。

11 月 28 日 13:51:54.449，内核记录 CH341 转换器从 ttyUSB0 断开，13:51:55.761 又识别为 ttyUSB0。新节点属性变更时间为 13:51:55.796。名称相同，设备节点重新建立，当前 ACL 已经没有之前的账号授权。检查时权限为 `root:dialout 0660`，现场账号和已打开的策略台进程均不属于 dialout 组。

14:17:29 至 14:17:47 的七个不同时刻均记录了串口打开失败，错误号为 EACCES（13）。回溯依次经过执行台的 guard、B1Gripper、open_gripper 和 pyserial 的设备打开函数。只读预览要取得真实夹爪开度，现有程序打开双向串口并查询设备身份。权限检查发生在打开串口时，早于设备身份查询、新会话归档和模型预测。单独重开策略窗口不会给设备节点添加权限。

14:18:55 的三秒被动 CAN 采样中，600 帧整机状态均为正常，六轴均报告使能，两段因果可分别定位到 J3 的历史报警和当前 USB 串口访问。11-27 腕部纠偏版本与 33 条回放记录对应的登记校验一致。本次只读取日志、节点属性和已有配置，没有改系统权限，没有启动预览或发送机械臂控制指令。[核验结果](outcomes.json) · [从诊断存档复算](summarize.py)
