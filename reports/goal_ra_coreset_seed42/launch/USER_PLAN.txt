综合 OBJECT、GOAL 以及 Event、SC-v1、SC-v2 的消融结果，我建议将 Coreset 重设计为“随机分布锚定＋最小损害的几何核心集”，同时建立稳定回放位置和独立动作随机流的统一实验协议。

新方案暂定名为 RA-Coreset（Reservoir-Anchored Coreset）。它不再强制恢复动作或时间比例，不增加事件配额，也不使用遗忘、损失、梯度冲突等代理评分。核心假设是：保留原 K-Center 的代表性，同时让一部分记忆来自原始数据的均匀抽样，可能缓解纯几何选样在 GOAL 上的分布偏置。

## 一、为什么需要重新设计，而不是继续调整 SC？

现有结果形成了比较明确的约束：

| 已完成实验                 | 直接结果                       | 对新设计的要求         |
| --------------------- | -------------------------- | --------------- |
| OBJECT Coreset，五 seed | 相比 Random，AUC 平均＋5.81个百分点  | 保留几何代表性         |
| GOAL Coreset，三 seed   | 相比 Random，AUC 平均−3.02个百分点  | 不能完全依赖最远点覆盖     |
| Event＋Coreset，五 seed  | 相比 Coreset，AUC 平均−4.29个百分点 | 不再强制增加操作事件比例    |
| GOAL SC-v1            | AUC 较 Coreset 下降5.31个百分点   | 不强制精确匹配离散监督比例   |
| GOAL SC-v2            | AUC 较 Coreset 下降9.69个百分点   | 不再把几何覆盖底线视为性能保证 |

更关键的是最新代码审计：SC-v2 在 Task 9 训练前只改变11个旧成员，却导致94.05%的 batch 样本集合发生变化；进入 Task 9 评估时，两组 CUDA 动作随机状态也不同。

这意味着过去的结果同时受记忆内容、训练样本编排、连续参数更新和评估噪声影响。

因此，下一版必须同时满足两项要求：提出真正不同的 Coreset 选择机制，并让比较尽量隔离选择机制本身的效果。

证据来自最新 [SC-v2 最终报告](https://github.com/uhhj/lifelong_mlr_ifa_minrep_20260821_193226/blob/95503d6799b14862d5d5d21ab065c8ba252863b2/reports/goal_scv2_seed42/completion/FINAL_REPORT.md?utm_source=chatgpt.com)和[机制审计](https://github.com/uhhj/lifelong_mlr_ifa_minrep_20260821_193226/blob/95503d6799b14862d5d5d21ab065c8ba252863b2/reports/goal_scv2_mechanism_audit/REPORT.md?utm_source=chatgpt.com)。

## 二、RA-Coreset：具体怎样重新选择记忆？

原 Coreset 的核心仍然保留：

\\[ S_C=\operatorname{KCenter}(U,q) \\]

其中 \\(U\\) 是当前任务全部训练窗口，\\(q=\lceil |U|/2\rceil\\) 是原来的记忆配额。

新方案不是重新聚类，也不是在每个时间段设固定名额，而是增加一组随机锚点（Random Anchors）。

### 第一步：从原始窗口中均匀抽取锚点

先按原 Random 入库规则，使用同一训练 seed 对全部当前窗口无放回抽样：

\\[ S_R=\operatorname{RandomSample}(U,q) \\]

取前一半作为固定锚点：

\\[ \boxed{A=S_R[:\lfloor q/2\rfloor]} \\]

这保证锚点是从原始训练窗口中均匀抽取的，但不保证最终 Buffer 的整体分布严格等于原始数据。

锚点的作用是让部分真实数据直接获得保存资格，而不是全部由几何最远点规则决定。

### 第二步：先保留原 Coreset，检查缺少哪些锚点

原集合为 \\(S_C\\)，随机锚点为 \\(A\\)。

只需补入：

\\[ M=A\setminus S_C \\]

如果某个锚点已经被 Coreset 选中，就无需重复保存。

因此，新集合的替换次数恰好为：

\\[ \boxed{|M|=|A\setminus S_C|} \\]

这是将全部指定锚点纳入原集合所需的最少成员替换次数。

### 第三步：每补入一条锚点，删除几何损害最小的旧成员

设当前集合为 \\(S\\)，准备加入锚点 \\(x\\)。只允许删除不属于固定锚点的成员：

\\[ y\in S\setminus A \\]

对所有合法删除对象，计算加入 \\(x\\)、移出 \\(y\\) 后的原始覆盖半径：

\\[ R(S')=\max\_{u\in U}\min\_{s\in S'}D(u,s) \\]

选择：

\\[ \boxed{ y^\*=\arg\min\_{y\in S\setminus A} R\big((S\cup\\{x\\})\setminus\\{y\\}\big) } \\]

半径相同则比较平均最近距离，仍相同时按照稳定样本 ID 决定。

距离 \\(D\\) 完全沿用已验证的视觉历史—专家动作距离，不改变 token、权重或标定。 与 SC-v2 不同，这里不强制要求最终半径一定不高于原 Coreset；它用于在必须加入随机锚点时尽量减少几何损失。

最终：

\\[ |S\_{\mathrm{RA}}|=q,\qquad A\subseteq S\_{\mathrm{RA}} \\]

不增加 Buffer 容量、不重复窗口，也不额外生成训练数据。

### GOAL 中实际的数量

| 任务 | 全部窗口 | 原入库配额 | 随机锚点数量 |
| -- | ---- | ----- | ------ |
| 6  | 997  | 499   | 249    |
| 7  | 889  | 445   | 222    |
| 8  | 904  | 452   | 226    |
| 9  | 1969 | 985   | 492    |

这里的“249条随机锚点”不表示一定替换249条 Coreset。实际替换数取决于已有 Coreset 与随机锚点的交集，应在离线选样完成后直接报告。

## 三、必须同步修复真实训练中的样本重排问题

这一步不是新选样目标，而是保证我们能够合理解释新选样效果的实验控制。

当前代码实际执行的是：

```
buf_paths = sorted(buffer_paths)mix_paths = buf_paths + current_task_pathsrandom.Random(seed).shuffle(mix_paths)
```

随后再由原 `DistributedSampler` 按 epoch 生成 batch 索引。

即使 RA 只替换少数 Buffer 文件，新文件名字典序也可能使大量共同样本的位置移动。这正是 SC-v2 审计发现的影响通道。

### 改成稳定槽位（Stable-slot Replay）

对每个已完成任务，先记录原 Coreset 在训练加载器中的真实排序位置。然后：

- 两组共同保存的旧样本，保持相同的加载位置。
- 被移出的 Coreset 成员留下一个槽位。
- 新加入的 RA 成员填入这些槽位。
- 当前任务完整数据、原 shuffle 和 DistributedSampler 规则不变。

例如：

同一个旧任务的加载槽位示意

槽 0

A

槽 1

B

槽 2

C

槽 3

D

槽 4

E

用新成员 X 替换 C

槽 0

A

槽 1

B

槽 2

X

槽 3

D

槽 4

E

示意的是身份到加载位置的映射，不是重命名真实样本文件。

它能保证共同成员在进入原 shuffle 之前的位置不变，但不能保证模型参数更新完全相同，因为真正替换的样本仍然不同。

严格基线复用条件： 使用原 Coreset 成员、不作任何替换时，Stable-slot 加载器必须对全部四阶段、全部100个 epoch 复现父加载器的样本身份顺序，并通过真实单步训练一致性检查。

如果验证失败，就必须重新运行采用共同加载器的 Coreset 基线，不能只对新方法使用不同加载器，再声称与历史基线严格配对。

## 四、闭环评估改为逐轨迹独立噪声

过去 SC-v1、SC-v2 已经证实：相同训练 seed、初始状态和评估规则，仍可能因前序任务运行步数不同，使后续动作随机流不一致。

因此，新评估协议 E1 采用方法无关的固定标准高斯噪声。

对于每条轨迹及其动作时刻，预先确定：

\\[ \epsilon\_{s,t,i,\tau}\sim\mathcal N(0,I) \\]

其中 \\(s,t,i,\tau\\) 分别对应训练阶段、被评任务、初态编号和动作步。所有比较方法使用相同对应噪声。

保持原 GMM 的最大 logits 分量选择：

\\[ \boxed{ a\_\tau=\mu\_{\mathrm{selected},\tau} +\sigma\_{\mathrm{selected},\tau}\epsilon\_{s,t,i,\tau} } \\]

不改成均值动作，不改原初态0–19、600步上限或成功判定。

这样一条轨迹提前成功，不会改变另一条轨迹后续动作的随机数来源。

重要的公平性代价：E1 是新的评估协议，旧 Coreset 和 Random 的 checkpoint 可以复用，但其历史 AUC 不能直接与新 E1 结果比较。 主比较至少需要用 E1 对原 Coreset 与 RA 共同评估。

### 首轮为什么先 GOAL seed 42？

因为 GOAL 是原 Coreset 连续三个 seed 输给 Random 的任务套件，属于更有针对性的失败检验。若新方法不能在这里改善结果，就不应仅通过 OBJECT 再找一个正向例子来宣布设计成功。

GOAL 正式训练协议：

| 项目          | 固定值                        |
| ----------- | -------------------------- |
| 预训练起点       | 原 GOAL 官方六任务权重             |
| 训练任务        | 6→7→8→9                    |
| 数据          | 原 `state=True` 特征、每任务10条示范 |
| 损失          | BC＋0.1×平均 IFA，gamma=0.7    |
| Epoch、batch | 每任务100 epoch，batch 10      |
| 优化器与调度      | 原 AdamW、warmup500、逐步线性调度   |
| 入库数量        | 499／445／452／985            |
| 模型选择        | 固定 epoch 99                |
| 新方法训练       | 400 epoch、76,100次更新        |

Task 6 训练时 Buffer 为空，RA 尚未发挥作用，因此首次入库前的实际模型参数应与原 Coreset 完全一致。Task 9 最后入库的样本则不会影响当前四阶段的任何评测模型。

### 需要做的工程验收

1. 原 K-Center 和 Random 选样逐身份复现；RA 满足全部锚点、配额和最少交换次数。
2. 原特征载荷、当前任务样本数、旧任务标签、每 epoch 曝光次数和优化步数不变。
3. 无替换时 Stable-slot 完整复现原加载器；发生替换时，共同旧成员保持原槽位。
4. E1 的噪声与算法名称无关；旧 C 和新 RA 使用相同逐轨迹噪声。
5. 4个 checkpoint 严格加载，全部训练日志、入库事务、逐 episode 与技术异常账目可独立复算。

不根据覆盖半径、选中动作比例或训练 loss 决定是否推进。那些只能用来解释选择器具体做了什么，效果判断完全由闭环指标完成。

## 六、单 seed 推进条件与总成本

首轮采用相同 E1 协议下的 RA−Coreset 配对差值，并预先冻结：

\\[ \boxed{ \begin{aligned} \Delta\mathrm{AUC}&>0\\\ \Delta\mathrm{FWT}&\geq0\\\ \Delta\mathrm{OldFinal}&\geq0 \end{aligned} } \\]

NBT 和逐任务成功率必须报告，但不单独用 NBT 作为推进条件，因为它可能被任务间成绩改善和初学锚点变化抵消。

门槛通过后，再共同评估 Random checkpoint，判断 GOAL 是否真正追平或超过 Random；随后检查 OBJECT seed42 能否至少维持原 Coreset 的 AUC、FWT 和最终旧任务表现。两个套件都通过，才扩展43、44等未在本轮设计中重新调参的 seed。

| 成本项             | 首轮 GOAL seed 42        |
| --------------- | ---------------------- |
| 新训练组            | 1组 RA                  |
| 新训练             | 76,100 optimizer steps |
| 新 RA 模型         | 4个                     |
| E1 原 Coreset 重评 | 200条闭环                 |
| E1 RA 评估        | 200条闭环                 |
| 原基线重训           | 0，前提是加载器等价性验收通过        |
| 新模型参数           | 0                      |
| 其他评估            | 门槛通过后才增加               |

这里的单 seed 仍属于探索性筛选，尤其 GOAL seed42 的历史结果已参与了方案设计，不能用它独立确认泛化。

## 八、研究价值与最后的取舍

RA-Coreset 相比先前方案有三个实质区别：

不再把随机采样视为需要完全替代的低级基线。 GOAL 上 Random 的优势是真实观察到的，因此保留一部分均匀随机数据支持有实验动机。

不再给时间、夹爪符号或事件定义强制配额。 减少人为约束与原 K-Center 之间的竞争，但随机锚点仍可能牺牲一定覆盖。

将训练加载顺序和评估随机流从隐藏混杂因素变成明确受控的协议变量。 这样即使新方案失败，也更容易判断失败来自记忆内容本身，而不是少数文件替换引起大面积无意重排。

但必须强调，随机锚点＋K-Center 不是天然新颖的基础思想。这套设计的优先目标是建立稳定有效的回放方法与可信实验基础；是否足够支撑顶会级算法创新，还需要后续比较现有混合核心集方法以及多 seed、跨任务套件的实证贡献。

我的最终建议是先执行 RA-Coreset 的离线选样和加载器等价性验收；通过后只启动 GOAL seed42 的完整闭环。暂时停止 SC-v3、Event 配额和残差叠加，避免再次在尚未确立有效性的选样机制上增加复杂度。
