# Pika USB 夹爪两次异常张开复核

2026-11-27，北京时间。现场在手动窗口和 B1 执行台各观察到一次意外张开。主机的目标开度、SDK 换算的目标角和电机回报的开度在两次事件中出现了明确分歧。B1 随后触发了整臂保护。现有记录能定位异常出现的环节，仍缺设备实际接收的目标值来区分更深一层原因。

| 入口 | 主机和 SDK 记录 | 电机反馈和保护 |
|---|---|---|
| 手动，20:27:18.264 | 当前 59.26 mm，要求收至 40.00 mm，SDK 目标 0.7691 rad。当时电机回报的位置为 1.0583 rad。 | 请求后 19.9 ms 开始向外运动，相电流从约 0.13 A 升至 0.63 A。32.7 ms 时程序请求失能，此前反馈已到 62.09 mm。随后最高 80.17 mm，失能请求约 102 ms 后得到确认。 |
| B1，20:32:27.467 触发保护 | 共 21 次执行目标，SDK 日志逐条吻合。目标从 64.31 缓升至 66.74 mm，末次目标角 1.1689 rad。 | 反馈达到 79.02 mm 时，上限为 78.74 mm，电机回报 7.725 rad/s、0.651 A。主机约 0.89 ms 后进入 STOP 处理。随后最高 96.07 mm，约 94.6 ms 后首次收到夹爪失能状态，执行台也记录了从臂 STOP 回执。 |

手动窗口在 20:28:32 再次请求 40.00 mm。这次从约 50.32 mm 出发，同一 SDK 目标角 0.7691 rad，最终稳定在 40.22 mm。两个事件中有完整位置、电流和速度的连续 USB 反馈。两段留存窗口的电压读数均为 24.2 V。对执行目标角进行正向换算，和请求开度最大相差 0.020 mm 以内。一次固定的方向、单位或夹口宽度换算错误难以解释这组结果。

另有一类可以区分的事件。20:26:17.740 附近，夹爪连续两帧回报零位置、零电流，前后均为 39.32 mm。那次由零读数触发保护。20:27 和 20:32 的意外张开在保护之前已有连续向外的电机运动反馈，并有现场目击。

两种入口共用同一 Pika USB SDK 位置指令。此次查看的 USB 抓包目录只有前一天的抓包。SDK 的写入成功记录无法证明控制板采纳了哪一个目标角。优先核查 USB 线上实际发出的目标与夹爪驱动的响应，尤其是目标角、速度、相电流和开度的方向关系。仅依据当前遥测也无法排除短暂供电扰动。现场确认腕部原线仍接着。标准版手册将 XT30 用于 24 V 供电，CAN 两针列为预留，控制走 USB Type-C。现场线束和板卡版本尚未核实，保留原线本身不足以判定有第二路指令。[松灵 Pika 产品手册第 4.2 节](https://cdn.shopify.com/s/files/1/0551/0630/6141/files/Pika_Product_User_Manual_beta_EN_ROS1.pdf?v=1792488910#page=56) · [Pika SDK 串口发送实现](https://github.com/agilexrobotics/pika_sdk/blob/master/pika/serial_comm.py)

## 核验方法

使用同一次开机中的主机单调时钟对齐，利用 B1 会话头的墙钟时间换算北京时间，毫秒值表示主机观测时间。开度由 USB 原始帧中的电机角度按部署版本的连杆几何换算，不是独立量具读数。SDK 目标角来自系统日志，保留四位小数。复算脚本使用 Python 标准库，依次传入私有的 B1 JSONL、手动异常 JSON、手动对照 JSON、零帧异常 JSON 和同时间的 SDK 日志文本。公开结果保存输入文件摘要和事件统计。
