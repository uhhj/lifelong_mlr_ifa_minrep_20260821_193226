# 旧完整 S 与最新门控 S 的耗时核对

用户记忆正确：已验收的旧完整 S 三个 OBJECT seed，纯 epoch 训练108.49–111.24分钟，正式向量评估16.13–17.71分钟，采集约3–4分钟；保存、准备等另计，每seed两三个小时符合记录。

最新完整 S 加入每10步同状态的 C/Q 双候选、两次训练探针测量和完整状态恢复。每seed物理训练更新从105500升至195300（1.851倍），另外还有探针及CPU全state复制/恢复/精确比较开销，不能只按更新次数推断总耗时。代码证明这些操作存在，但尚无各操作的耗时剖析，不能断言哪项是首要瓶颈。

22:02真实快照中，seed41 Task7已完成60轮，全60轮均90.83秒、近10轮56.23秒；旧S Task7平均12.42秒。更关键的是，没有门控的Task6也由旧实测7.03分钟增到本轮26.91分钟，因此还有本轮运行速度变化，不能把全部差异归因于门控。现有证据不足以判定是GPU资源、CPU状态复制、磁盘或其他负载造成。

此前给出的24–40小时是按当前速度、未运行阶段的外推及波动余量估出的三seed训练、评估、验收规划范围，不代表算法必然需要这么久。应明确区分方法新增计算和当前实现/运行条件的开销。此核对不更改科学协议，不停止或重启现有训练，也不恢复已取消机制实验。

精确标量、文件SHA与代码出处见RUNTIME_COMPARISON.json。所有计算均仅读取已有记录，没有新增训练或环境调用。
