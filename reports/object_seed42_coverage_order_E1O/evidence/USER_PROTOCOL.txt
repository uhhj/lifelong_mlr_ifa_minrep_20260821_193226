**下一轮只运行 E1-O（全覆盖保护性重排）：从 E0 的完整遍历方式出发，用 E1 的评分调整部分旧样本进入不同更新步的顺序，严格保持每个样本的使用次数、每批任务构成和训练预算不变；已有 E0、E1、E1-U 均不重跑。**

现有结果为 E0 AUC 77.708、E1 77.292、E1-U 73.646，支持继续检验“保留评分、恢复完整覆盖”，但尚不保证重排有效。下面固定一套实现，不同时搜索多种重排范围或评分频率。

# 一、实验定义：只改“什么时候训练”，不改“训练多少次”

## 1. 本轮唯一研究问题

> **在每个epoch仍完整使用原buffer、每个样本的出现次数不变时，保护性重排能否提高LIBERO-OBJECT的总体闭环指标？**

需要保留以下硬约束：

| 维度 | E1-O要求 |
|---|---|
| 入库与淘汰 | 完全沿用原规则 |
| 每epoch旧样本集合 | 与E0相同 |
| 每个旧样本的使用次数 | 与E0相同；当前单卡完整遍历下为每epoch一次 |
| 当前任务样本 | 身份、位置、出现次数均不变 |
| 每个batch的任务ID排列 | 不变 |
| 新旧样本数量与各旧任务数量 | 逐batch不变 |
| BC、IFA、优化器、调度器 | 不变 |
| **允许变化** | **同一旧任务的样本，进入哪个优化步** |

原循环使用完整数据集和打乱后的 `DistributedSampler`。本轮保留其生成的样本集合与计数，只在索引层进行排列。

**E1的“50%旧位置有放回替换”不再启用。** 本轮也不调整累计频率，不增加样本损失权重，不接入E2。

## 2. “完整覆盖”不等于“给整个buffer反复评分”

首版采用**预算受控的局部重排**：每500个优化步，每个旧任务最多给64个待用样本评分并重排，其余样本保留E0原顺序。

因此，本轮保证的是：

\[
\boxed{\text{全部样本仍被使用，但只有部分位置接受保护性顺序调整。}}
\]

这样避免把采样结构改进变成全buffer高频梯度扫描。若本轮没有收益，结论只适用于这一有限重排预算，不能据此否定所有保护性排序方案。

# 二、算法流程：先生成原序列，再对未使用的位置做排列

## 步骤1：每个epoch生成一次E0原始索引序列

沿用原任务数据集、原采样器、原 `set_epoch(epoch)`，得到本epoch的基准序列：

\[
I_e^{0}=(i_1,i_2,\ldots,i_{N_e}).
\]

复制成实际训练计划 \(I_e\)。之后只修改 \(I_e\)，保留 \(I_e^0\) 用于核验。

**原采样器每epoch只迭代一次。** 不能为了日志或排序再次遍历它，也不能在每次调度时新建DataLoader迭代器，避免意外改变随机状态。

## 步骤2：低频选择可以重排的未来位置

在阶段内优化步：

```text
0、500、1000、1500……
```

执行一次调度。调度必须发生在读取对应训练batch之前。

本次可操作范围为：

> 从当前尚未读取的batch开始，到“下一次500步调度”或“当前epoch结束”，取先到达的边界。

只允许重排这个范围内的**尚未使用位置**，不跨epoch，不修改已经训练过的前缀。

首版固定保护两类位置：

**每个batch的第一个位置不动。** 这样不改变原IFA实现读取的首条参考，避免通过修复或改变IFA产生混杂。

**最后一个不满batch的所有位置不动。** 这样不把样本移入或移出具有不同平均损失归一化尺度的末尾batch。

其余位置中，对每个旧任务 \(j\)，均匀抽取最多64个位置：

\[
P_j=\{p_1<p_2<\cdots<p_m\},\qquad m\leq64.
\]

这些位置原本对应的样本组成候选集合 \(C_j\)。候选必须全部来自该任务本epoch尚未使用的样本。

如果不足两个位置，或者所有位置都属于同一个优化步，则不重排该任务。**只交换同一个batch内的行顺序，不是本轮需要验证的干预。**

## 步骤3：沿用E1的保护性评分

本次调度的数据定义如下：

| 数据 | 来源 | 数量 |
|---|---|---:|
| 候选 \(C_j\) | 当前重排区间内、旧任务 \(j\) 的待用样本 | 每任务最多64 |
| 历史参考 \(H_j\) | 当前合法buffer，排除本次该任务候选 | 每任务最多16 |
| 当前参考 \(N\) | 当前任务合法训练数据 | 最多16 |

参考样本只用于计算评分，不额外执行优化器更新。它们不是独立测试集，也不增加历史数据访问权限。

仍使用GMM策略头参数 \(\phi\) 的BC梯度：

\[
g_i=\nabla_\phi \ell_i,\qquad
g_H=\frac1J\sum_{j=1}^{J}\nabla_\phi\overline L_{H_j},
\qquad
g_N=\nabla_\phi\overline L_N.
\]

评分保持：

\[
\boxed{
s_i=
\cos(g_i,g_H)
-\max\!\left(0,-\cos(g_i,g_N)\right)
}
\]

历史任务均衡平均、冲突系数1、数值阈值 \(10^{-8}\) 均沿用E1。现有 `head_gradient()`、`protective_score()` 和评分模式隔离代码可以复用；时序解码器只做无梯度前向，候选只计算头部梯度。

**不能直接复用E1的候选构造方式。** E1从全缓存抽小池；E1-O必须从本epoch尚未使用的位置抽候选。两者的评分公式相同，但不再要求候选ID与E1逐项配对。

## 步骤4：生成保护性“无放回排列”

对候选赋予权重：

\[
w_i=\exp(s_i/\tau),\qquad \tau=1.
\]

按以下规则生成完整排列：

\[
P(\pi_r=i\mid\text{尚未排列的候选})
=
\frac{w_i}{\sum_{k\in\text{尚未排列的候选}}w_k}.
\]

每选出一个样本，就从待排列集合中移除，直到所有候选恰好出现一次。

然后将排列填回原来的同任务位置：

\[
I_e[P_j]\leftarrow
(C_{\pi_1},C_{\pi_2},\ldots,C_{\pi_m}).
\]

这使高分样本**更可能较早出现**，而不是出现更多次。低分样本不能被丢弃，也不能推迟到下一epoch。

不采用全局分数硬排序，不反复从64个样本中有放回抽取，也不修改没有被选中的位置。

## 步骤5：正常训练，完成后核验计数

按修改后的索引读取batch，执行一次原BC＋IFA更新。没有虚拟模型，没有多比例试训，也没有额外闭环控制器。

每次重排及每个epoch结束时都检查：

\[
\boxed{
\operatorname{Counter}(I_e)
=
\operatorname{Counter}(I_e^0)
}
\]

同时检查每个位置的任务ID相同、当前任务样本身份相同。

**不能只检查“唯一ID数量相同”。** 必须比较每个ID的次数，才能发现某个样本重复、另一个样本遗漏的错误。

### 回退规则

历史梯度无效时，本次整个重排不执行；当前梯度无效但历史梯度有效时，沿用E1的历史项评分并记录回退。

某个候选梯度无效时，首版让**该任务本次重排整体退回原序**，不能直接删掉这个候选。候选分数完全没有区分度时也保留原序。

重排以完整排列为单位提交；任何约束检查失败，都回滚整个对应排列。**不能只撤销一个位置的移动，否则可能产生重复或遗漏。**

### 评分预算上限

沿用500步调度，三个有回放阶段最多对应：

\[
46\times1+62\times2+73\times3=389
\]

个“调度×旧任务”评分集合，因此候选逐样本评分最多：

\[
389\times64=24,896.
\]

这些调度数量来自已有实验记录；由于epoch边界、锁定位置及小集合跳过，实际数量可能更少。

相对于本序列460,300个旧样本训练位置，最多约**5.41%**的位置参与评分重排。这是首版明确的干预范围，**不是继续让50%的旧位置从高分小池中抽样**。

这个上限约束了候选评分量，但不保证墙钟时间与E1相同；索引管理、参考计算和日志成本仍须实测。

## 1. 使用已验证的OBJECT代码，不改GOAL分支实现

| 位置 | 本轮处理 |
|---|---|

## 2. 索引重排必须发生在样本读取前

当前训练循环是采样器直接驱动DataLoader。需要增加一个读取可变索引计划的批采样器，**每次只取下一批索引，不提前复制整份已排好序的计划**。

本轮保持 `num_workers=0`。不能开启后台预取后，再修改已经交给worker的位置。

逻辑结构如下，函数名均为拟新增接口：

```python
for epoch in original_epoch_loop:
    original_sampler.set_epoch(epoch)

    # 原采样器只迭代一次。
    base_indices = list(iter(original_sampler))
    plan.begin_epoch(base_indices)

    # 每个epoch只建立一次DataLoader迭代器。
    loader_iter = iter(planned_loader)

    while plan.has_unread_batch():
        if should_schedule(stage_optimizer_step):
            reorder_unread_positions(
                plan=plan,
                policy=policy,
                legal_buffer=buffer,
                current_data=current_data,
            )

        batch = next(loader_iter)
        record_original_and_actual_ids(plan, batch)

        # 调用不带E1替换hook的原更新。
        loss = original_observe(batch)
        stage_optimizer_step += 1

    assert_epoch_multiset_and_slots_unchanged(plan)
```

身份日志必须记录**实际交给模型的ID**，不能只记录计划后就假定DataLoader执行正确。

## 3. 随机数和恢复规则

候选位置抽样、参考抽样、排列抽样使用独立随机数生成器，不消耗原DataLoader、入库或模型训练使用的随机流。

评分期间沿用已有随机状态与模块模式隔离；结束后恢复所有状态。正式检查包含模型参数、模型缓冲区、优化器状态及 `.grad`，不只是检查有没有执行 `optimizer.step()`。

首版沿用**epoch边界恢复**。保存模型、优化器、调度器、训练随机状态、重排随机状态、阶段步数和已提交日志位置；不宣称支持未实现的中途精确恢复。

## 4. 预检只做软件检查和短GPU检查

正式实验前必须通过：

| 检查 | 通过条件 |
|---|---|
| 覆盖与计数 | 原序列与实际序列的ID计数完全相同 |
| 位置约束 | 当前样本、任务排列、首位置和末尾不满batch不变 |
| 边界处理 | 不跨epoch、不修改已使用前缀、不重复排列已提交区间 |
| 回退 | 禁用模块、无效梯度、无区分分数均恢复原序 |
| 评分隔离 | 参数、优化器及正常训练随机状态不被评分改变 |
| 实际读取 | 模型收到的样本ID与计划一致 |
| 恢复 | epoch边界保存恢复后的后续索引和随机状态一致 |

在临时状态上进行少量GPU优化调用，测试后全部丢弃，再从规定预训练起点正式训练。**不为了检查索引而重跑一遍E0训练或增加闭环试验。**

# 六、结果判定、机制日志与交付

## 1. 总体指标决定是否保留

| 版本 | 主AUC ↑ | 主FWT ↑ | 主NBT ↓ |
|---|---:|---:|---:|
| E0，已有 | 77.708 | 77.500 | −0.278 |
| E1，已有 | 77.292 | 76.250 | −3.333 |
| E1-U，已有 | 73.646 | 76.250 | 7.222 |
| **E1-O，本轮** | 待测 | 待测 | 待测 |
| **E1-O−E0** | **主比较** | 差值 | 差值 |

已有结果来自归档；本轮用整数成功次数和原聚合公式计算未舍入指标，再进行比较。

主AUC继续按“每任务引入后的阶段平均，再对任务平均”计算，不能直接平均三角矩阵所有单元。FWT、NBT沿用原实现，不截断负NBT，也不增加事后综合分数。

**只有 E1-O 主AUC超过E0，才满足补齐seed43、44的条件。** 仅超过失败的E1或E1-U，不算通过。次口径、单任务结果和内部评分不得替代这个门槛。

若通过，冻结实现与参数，再补齐三seed；对应E0结果读取已有工件，缺失时明确配对证据不足，不自动重跑基线。

## 2. 机制日志检查“是否真的改变了更新时机”

本轮应记录：

| 日志内容 | 用途 |
|---|---|
| 每epoch基准索引与实际索引 | 证明完整覆盖及次数一致 |
| 每batch原始ID、实际ID、任务ID | 证明逐批约束及实际执行 |
| 每次重排的候选位置、分数、排列 | 核查评分如何影响先后 |
| 样本前移/后移的优化步数 | 区分跨batch重排与无意义行交换 |
| 候选数、跳过及回退原因 | 明确真实干预规模 |
| 原始梯度评分的两项分量 | 区分历史对齐与新任务冲突，不额外计算梯度 |

不要继续把“整个阶段99%重复率”作为主要诊断。100个epoch完整遍历本就会重复使用样本；本轮真正需要核验的是**每epoch无遗漏，以及评分是否改变了样本进入优化步的时机**。

重排改变率低、候选大多没有跨batch移动时，应如实记录；不能在正式运行中为了“让干预更强”临时修改范围。

## 3. 成本与解释边界

记录训练总时间、评分时间、重排管理时间、日志和检查点开销、主次评估时间及峰值显存。嵌套I/O不重复累加。

**评分数量上限接近E1，不意味着总耗时必然相同；恢复完整覆盖也不意味着闭环性能必然改善。**

本轮与E0的比较检验“有限预算保护性重排”的总体效果。与E1/E1-U的比较仅作辅助，因为候选来源、使用次数分配和排序机制都发生了变化，不能再称为同池单变量配对。

## 4. 最终交付与停止点

保留独立的源码差异、冻结合同、输入哈希、400个epoch记录、28个检查点哈希、880条闭环记录、覆盖与重排审计、总体结果表及成本报告。既有实验目录只读，不覆盖完成标记或恢复文件。

**完整执行顺序是：隔离代码与输入 → 实现未来索引的无放回重排 → 短预检 → seed42完整训练 → 原协议闭环评估 → 以总体AUC对比E0决定是否补seed。**

**本轮的成功标准不是“排序更符合保护分数”，而是“在不牺牲E0完整覆盖与见样次数的前提下，总体闭环指标真正超过E0”。**
