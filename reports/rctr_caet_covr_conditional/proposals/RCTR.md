## 三、RCTR 的正式算法定义

这里采用一个固定版本，记作 RCTR-v1。本轮不搜索多个算法变体，也不依据 seed42 的结果修改超参数。

### 1. 反事实数据如何生成

RCTR 不使用已经证明难以精确复现的旧 HDF5 中间状态。

每学完一个任务，使用当前阶段的冻结策略，在其自身任务环境中执行并采集真实可达状态。

在 Task6、7、8 结束后各进行一次采集；Task9 结束后不再采集，因为后面没有新增任务需要回放。

每次采集使用以下预先固定的配置。

| 项目        | RCTR-v1 配置                          |
| --------- | ----------------------------------- |
| 采集策略      | 当前任务刚训练完成的 ep99 checkpoint          |
| 采集任务      | 仅当前任务，不访问未来任务                       |
| 初态索引      | 20–25，与正式评估的 0–19 分离                |
| 状态采集时间    | 第 40、120 个策略控制步                     |
| 最大状态数     | 每任务 12 个                            |
| 动作干预      | 前三个连续动作维度各 ±0.05                    |
| 干预方向      | 6 个                                 |
| 恢复候选      | 原赢家 Gaussian 采样、logits 最高的两个非赢家分量均值 |
| 探索重复      | 每候选 2 次匹配随机噪声                       |
| 独立复核      | 每候选额外 2 次，且仅复核预筛选候选                 |
| 每任务有效记录上限 | 12 组控制响应记忆                          |

初态数量必须在预检时确认。若原始初始化文件不包含索引 20–25，则暂停工程执行，不擅自改用正式测试初态。

当某条轨迹在第 40 步前已经成功时，后续采集点标记为不可用，不从其他初态临时补选。

关键要求：保存完整仿真快照，而不只是 MuJoCo flat state。

快照必须包括 MuJoCo 积分状态、控制器和夹爪内部状态、观测缓存、八步历史、必要的环境随机数状态。两次从相同快照执行相同动作与噪声，必须通过原生状态与观测一致性验证。

这部分可以借鉴已经完成的 [RCTR Stage A2 实现](https://github.com/uhhj/lifelong_mlr_ifa_minrep_20260821_193226/blob/MLR/reports/rctr_goal_seed42_stageA2/PROTOCOL.md?utm_source=chatgpt.com)，但不能直接把 GOAL 的状态、恢复结果或采集数据用于 OBJECT。

### 2. 什么样的反事实结果才能用于训练？

对同一个状态，首先执行正常动作和指定扰动，得到两个真实可达的后续状态。

在扰动后的状态上，比较默认恢复动作与其他候选动作。

这里不再要求旧方案的全部 3/3 成功、0/3 失败，而使用两级认证：

探索认证： 两次匹配噪声中，替代候选相对默认恢复至少挽救一次失败，并且不新增成功变失败。

独立复核： 使用两条未参与探索的噪声轨迹重复比较，也要求至少一次挽救、没有反向损害。

只有同时满足两级条件的候选才能进入训练 sidecar。

如果相同状态有多个合格候选，只保存按预定排序确定的一组，避免同一个状态重复占用大量记忆。

对于正常分支和恢复分支在同一次匹配试验中均成功的记录，保存完整控制响应监督：

\\[ (z^0,z^\delta,a^0,a^+,a^-) \\]

其中：

- \\(z^0,z^\delta\\)：两种真实可达状态对应的八步原生潜在特征；
- \\(a^0\\)：正常成功分支实际执行的参考动作；
- \\(a^+\\)：扰动状态下经过成功认证的恢复动作；
- \\(a^-\\)：同状态下经过配对验证的失败或较差动作。

若没有可信的正常成功参考，只允许保存恢复动作偏好，不伪造控制响应标签。

认证不能证明候选动作具有普遍最优性，它只表示在已记录状态和噪声条件下观察到可重复的结果优势。

### 3. 需要执行多少额外仿真？

每任务最多 12 个快照，每快照包含 1 个正常分支及 6 个干预方向、每方向 3 个恢复候选。

这属于上限而非必须跑满的目标：提前成功、无效干预、不可用快照均应如实记录，不进行结果驱动的补选。

特别注意：每次分支的剩余策略步数不得超过 \\(600-t\\)，其中 \\(t\\) 是采集快照之前已执行的策略步数。不能在第 120 步的状态重新额外赋予 600 步，否则辅助成功认证与正式任务时限不一致。

## 四、RCTR 如何参与持续学习训练？

### 1. 网络结构完全沿用原方法

不增加新的残差网络、任务专属 adapter 或推理路由器。

仍然只训练：

- Temporal Transformer；
- GMM Policy Head。

前端编码器沿用原有预训练权重和冻结规则。

RCTR 新增的是训练监督，并非部署模型参数。

### 2. 联合损失

继续使用：

\\[ \mathcal L\_{\mathrm{base}} = \mathcal L\_{\mathrm{BC}}+0.1\mathcal L\_{\mathrm{IFA}} \\]

RCTR 包括三部分：

\\[ \mathcal L\_{\mathrm{RCTR}} = 0.1\mathcal L\_{\mathrm{response}} +0.02\mathcal L\_{\mathrm{route}} +0.02\mathcal L\_{\mathrm{pref}} \\]

总损失：

\\[ \boxed{ \mathcal L\_{\mathrm{total}} = \mathcal L\_{\mathrm{BC}} +0.1\mathcal L\_{\mathrm{IFA}} +\mathcal L\_{\mathrm{RCTR}} } \\]

这些系数是本轮建议冻结的实验超参数，不是已有实验验证出的最优值。

三项监督分别定义如下。

控制响应保持

\\[ \mathcal L\_{\mathrm{response}} = \left\\| D^{-1} \left[ (\mu\_\theta^\delta-\mu\_\theta^0) -(a^+-a^0) \right] \right\\|^2 \\]

其中 \\(\mu\_\theta^0,\mu\_\theta^\delta\\) 采用与已认证动作最近的 GMM 分量均值，分量索引匹配停止梯度；\\(D\\) 使用预训练任务动作分布预先确定的尺度，对前六个连续动作维度归一化。

执行路由保持

\\[ \mathcal L\_{\mathrm{route}} = \left[ 0.1+\max\_{j\ne j^+}\ell_j-\ell\_{j^+} \right]\_+ \\]

它确保成功动作对应的分量有机会成为实际执行的赢家。

成功／失败动作偏好

\\[ \mathcal L\_{\mathrm{pref}} = \operatorname{softplus} \left(0.1+S\_\theta(a^-)-S\_\theta(a^+)\right) \\]

其中 \\(S\_\theta\\) 使用实际被选中分量的标准化动作距离构造，越接近目标动作得分越高。

对夹爪维度单独检查动作符号和执行分量，不把开合切换当成普通连续位移差分。

所有比较在构建 sidecar 时保存原始候选动作，训练阶段不重新运行历史教师。

### 3. 每次优化器更新如何处理 RCTR？

原来的正常 batch 仍为 10 个样本，按原数据加载顺序计算 BC＋IFA。

每次实际更新最多额外读取 一组旧任务 RCTR 记录。从当前已学完的旧任务 sidecar 中，按照固定轮转顺序抽取，使用独立的本地采样状态，不触碰原训练全局随机数流。

这样可以保证：

- 每 epoch 的正常样本和原 shuffle 不变；
- 原 IFA 的计算公式和参考集合不变；
- 每个原 batch 仍只调用一次优化器；
- 不会因为新任务数增加而无限放大辅助损失；
- RCTR 数据不会冒充原 RA buffer 的演示样本。

Task6 没有旧任务控制记忆，因此 RCTR 项严格为零。

Task7 使用 Task6 的 RCTR；Task8 使用 Task6、7；Task9 使用 Task6、7、8。

单任务 RCTR 最多保存 12 组、每组两个 `(8,4,512)` float32 特征窗口，核心特征载荷约 1.5 MiB/任务。三项旧任务合计最多约 4.5 MiB，另计动作、索引和认证元数据。必须报告这部分额外记忆，不得称为零开销。

扩展后，以每个 seed 配对的 RA-Coreset＋IFA 为对照，报告：

\\[ \Delta\_{\mathrm{AUC}}(s) = \mathrm{AUC}\_{\mathrm{RCTR}}(s) - \mathrm{AUC}\_{\mathrm{RA}}(s) \\]

建议将“三 seed 平均 AUC 严格提高，至少 2/3 seed 的 AUC 提高，且没有严重的 FWT 或 FinalAll 退化”作为本轮跨 seed 成功标准。即使有一个 seed 负增长，也必须完整披露。

还应单独报告新增环境交互数量、辅助记忆字节、训练时间和 GPU 成本。若三 seed 均有收益，后续论文至少需要等额外数据预算的普通 BC、普通功能蒸馏和去掉 RCTR 路由项的消融，才能证明收益来自所提出的机制，而不是单纯增加训练数据。
