# RCTR零认证原因与继续价值：已有数据只读分析

结论：不建议继续原样扩seed或重复RCTR-v1完整训练。当前失败首先发生在监督信号生成，而非辅助损失优化。可以保留在线完整快照和配对反事实比较的工程能力，但若继续研究，应先重新证明“可重复的局部动作优势”存在，不能再先投入完整持续学习训练。本次不增加任何训练、环境步或改变已部署条件队列。

数据：已完成OBJECT42的1388个committed分支、原正式200条、已验收训练账目；读取本地progress_20261021_094302/DETAILS.json。collect.py和loss.py逐SHA与rctr42_admission/CONTRACT.json一致。新增脚本analyze_rctr_failure.py独立复算，结果见ANALYSIS.json，脱敏分支元数据见BRANCH_OUTCOMES.jsonl。

## 一、三个任务是三种不同的失败

|采集任务|正常分支成功|扰动后默认恢复成功|两个非赢家候选成功|候选相对默认：失败→成功/成功→失败|进入复核的快照|最终认证|
|---|---:|---:|---:|---:|---:|---:|
|Task6|3/24|20/144|30/288|2/12|1|0|
|Task7|24/24|144/144|288/288|0/0|0|0|
|Task8|23/24|140/144|285/288|7/2|4|0|

正常分支为12快照×2噪声；默认为12快照×6扰动×2噪声；候选另乘2个非赢家分量。这些不是独立同分布episode，尤其默认结果被两个候选共用，不能直接做独立样本显著性检验。辅助续跑使用初态20–25及匹配噪声，与正式0–19/global RNG不同，表内成功率不能直接与正式成功率比较。

Task6：12个快照中8个，正常、扰动默认、全部候选在两份探索噪声下全失败。并非没有失败机会，而是所测试的候选几乎无法修复。只有初态23、第40步的一个候选通过探索（一次挽救、一次双方成功）；更换独立噪声后两次双方失败。两个角色的描述性比较分别是0次挽救/7次伤害、2次挽救/5次伤害。没有证据支持继续增加相同候选的完整训练。

Task7：456个探索分支全部成功，所有12个快照的扰动默认也全成功。认证要求默认失败而候选成功，因此这里没有可识别的修复机会。不能将零认证解释为候选错误或控制响应不存在，但这些分支不能支持“挽救失败”。

Task8：存在稀疏探索优势，但4个入选候选独立复核时，8对比较全部双方成功（共16条分支全成功）。因此未认证不是候选在复核中失败或造成反向损害，而是默认控制也成功，无法复现相对优势。这与少量噪声条件下的偶发失败一致，但仅2份复核噪声不能确定真实优势严格为零。

## 二、根本问题不是简单把认证阈值调松

1. **采集状态没有对准“可由局部动作修复的错误”。** 每个任务刚学完就在固定40/120步取快照；不根据错误发生时刻定位。Task6大量全失败、Task7/8大量全成功，样本集中在任务成败的两端，而不是候选动作能稳定改变结局的边界。是否已错过抓取、接触或释放时机，当前元数据无法判断；不能据此编造具体物理失败原因。

2. **候选来源缺少独立纠错能力。** 当前只从同一策略的两个最高logit非赢家Gaussian取均值，在扰动后第二步替换一个7维动作，再立即回到原策略。GMM分量编号不是经过验证的“抓取/恢复技能”；两个非赢家均值也不保证代表正确动作。如果错误需要多步轨迹、姿态与夹爪的协调，单步切换可能不足。Task6的2次挽救对12次伤害支持“当前候选池不够可靠”，但不足以证明所有更长控制或其他候选都无效。

3. **随机XYZ扰动并未可靠制造待修复错误。** 原实现仅对一帧前三个动作坐标加±0.05，不针对真实失败因素。与相同噪声的正常分支比较，Task6扰动造成3次成功→失败、同时5次失败→成功；Task7两者均0；Task8也是3次成功→失败、5次失败→成功。这里每个正常结果被6方向共用，仅为描述性计数。现有数据不支持“这些扰动系统地产生了需要新控制响应的错误状态”。

4. **稀疏终局二值成功使局部识别效率低。** 单次动作后仍需原策略续跑至总600步；后续噪声和后续决策可消除或放大当前动作影响。实现已在相同快照、相同重复编号内使用匹配噪声，不能把本轮零认证归罪于正式评估的未隔离global RNG。配对能减少噪声差异，却不能让局部动作优势跨所有噪声自动稳定。

5. **生成时机与遗忘问题错位。** 只在任务自身刚训练完成时采集，之后不针对旧任务的实际退化更新。正式Task6是30→80→35→10：最明显退化发生在学Task8/9之后，采集却在最初Task6仅30%的模型上完成。这是结构性目标错位的证据，不是具体物理错误的定位。即便早期有认证样本，也未证明它们覆盖后来遗忘导致的新错误。

## 三、哪些怀疑目前没有证据支持

- 不是“loss太弱/系数过小”的实验证据：三阶段sidecar全空，105500次主更新辅助项均未激活；response/route/preference的学习效果均未被检验。
- 没有证据显示本轮是状态恢复错误：在线恢复门、原生接口、冻结输入和完整账目已通过。不能把旧历史演示恢复失败直接套到这次在线快照上。
- 不是“只修夹爪”：本轮候选替换的是完整7维动作；局限在单步替换和候选来源。扰动只作用前三个坐标是另一回事。
- 不能称Task8复核证明候选有害：实际双方全成功。
- 不能通过事后将双方成功也计为“修复”来挽救本轮结果。那会把修复成功标准改成普通成功行为保持，属于新方案。

## 四、成本和研究优先级

分支执行时长合计约6.756小时（不含前缀、恢复检查、模型加载等）；Task6约4.845小时，占71.7%，Task7约0.620小时，Task8约1.291小时。主训练累计约0.892小时，正式评估参考约1.321小时。长时间来自大量接近步数上限的失败续跑，不是100epoch本身。

原样RCTR-v1的继续价值低：重复完整seed主要会再检验同一个低产率的数据生成器。增加重复次数可能提高稀疏信号检出率，但没有先验证候选质量，就容易用更多交互购买同样的零信号。当前证据支持暂停这条原样路线，不支持通过放松阈值、重复筛选候选或反复重跑得到正结果。

值得保留的是完整在线快照、原生潜特征一致性、匹配噪声反事实和独立确认的工程能力。若未来重启研究，应先证明三件事：固定的一批真实失败有可恢复状态；某个具备额外纠错能力的候选在这些状态上跨噪声有正向净优势；这些状态与后续遗忘有关。任一项缺失，都不值得再次完整重训。这里没有指定或批准新交互预算，本轮仅提出研究优先级。

已排队的COVR在后续任务训练中访问旧任务真实失败，且比较5个分量与默认及赢家均值，是对采集目标更直接的检验；但仍受同模型候选和单步干预限制，不能预先承诺有效。继续既定COVR比额外重跑RCTR更有信息价值；无需改变当前队列或增加实验。

最终判断：**放弃原样继续RCTR-v1，保留反事实工程基础；暂不据此否定所有控制响应监督，但将“产生可靠局部优势”作为下一次投入训练前必须先证明的事实。** 本轮只是单seed事后分析，没有统计显著性或普遍因果结论。
