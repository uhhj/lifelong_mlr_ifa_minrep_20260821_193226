## 顺序与比较对象

依次执行 RCTR、CAET、COVR，均与 RA-Coreset＋IFA 组合。每套先做 OBJECT seed42；对应基线是同数据集、同 seed、原协议下的 RA-Coreset＋IFA，不是 Random 或普通 Coreset。复用已完成基线，不重训或重评。

1. OBJECT seed42 完整验收通过，且原项目 AUC **严格高于**对应基线，才固定补跑 OBJECT seed41、43。
2. seed42 未提高（包括相等）：记录完整负结果，转入下一套方案。
3. OBJECT 的三个 seed 全部完整验收后，计算 seed41、42、43 等权平均 AUC，与三个对应 RA＋IFA 基线的等权平均 AUC 比较。
4. 平均 AUC **严格提高**：继续同一方案 GOAL seed41、42、43，复用对应 GOAL RA＋IFA 基线。GOAL 三 seed 按固定预算全部执行，不根据其中某 seed 的好坏提前停止。
5. OBJECT 三 seed 平均 AUC 未提高（包括相等）：跳过本方案 GOAL，进入下一套。GOAL 三 seed 全部验收后也进入下一套，不递归扩展。
6. 三套方案全部完成其应执行分支后，运行 RA-Coreset＋IFA 的 LIBERO-50 seed41、42、43。

“高于基线”在三 seed 判断中采用配对 seed 的平均 AUC 差大于零；不要求每个 seed 均提高，不添加“至少两个 seed 提高”、OldFinal、FWT、最低辅助记录数等未获最新授权的额外扩展门槛。所有指标及负结果仍完整报告。工程与真实性验收不能取消。

AUC 必须从完整逐 episode 记录复算：每个任务从学完到最后阶段的成功率先平均，再对任务平均；不能直接平均十个矩阵格，也不能对已四舍五入的百分数作门槛比较。使用有理数比较，持平不扩展。

## 协议与安全恢复

算法及辅助交互预算依各附件；以上规则只覆盖附件中相冲突的扩展门槛、跨套件顺序和 seed 范围。OBJECT 任务6–9的每任务100 epoch、BC＋0.1 IFA、gamma0.3及原正式200条闭环保持不变。GOAL 对齐现有 GOAL 协议（包括 gamma0.7 和相应窗口/步数），不能照抄 OBJECT 的样本数。LIBERO-50 必须先核实官方任务划分、权重、数据及预算，不伪称资产已齐全。

工程错误不作为“无增益”，不能因此静默跳过方案。先保留失败/退出/全部尝试，核对冻结合同，再做协议内恢复。只能恢复未完成工作；正常任务失败不重试，不扩大交互预算，不改变损失/阈值/数据/采样规则。无法在这些条件内恢复时保留证据并停止等待具体解决条件，不能无限盲重启。

未通过工程验收、尚在运行、缺少记录、资源缺失或真实性核验失败，都不得进入数值扩展判定。正式部署前必须冻结完整训练入口、采集预算、阶段事务与独立验收器。仅上传本规则或判定程序，不表示完整服务器队列已部署。
