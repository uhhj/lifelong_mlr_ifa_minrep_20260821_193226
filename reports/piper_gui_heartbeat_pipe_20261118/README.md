# PiPER 本机管道心跳与离线验收

上位机的 Qt 定时器按 100 ms 周期，通过 `QProcess` 子进程的标准输入管道发送单调时间戳。转发进程用非阻塞方式读取，首个有效心跳到达后才打开 CAN 控制套接字。正常绑定路径不再读写 `panel.json`。

500 ms 的 STOP 条件保留。接收端检查心跳年龄及发送时间戳之间的间隔，达到 500 ms 进入既有停止路径。管道断开也会触发停机。收到一条迟到的新心跳无法掩盖之前达到 500 ms 的间隔。手动 STOP 和独立控制进程看门狗保持原通路。

每次绑定的 `heartbeat.jsonl` 记录 `interval_ms`、`receive_interval_ms`、`pipe_delay_ms`、发送和接收的单调时间戳，以及心跳失败事件。该日志由后台记录线程写入。同一目录的 `can_timeline.jsonl` 保持原格式，可按单调时钟对齐。

2026-11-18 在服务器隔离目录完成 61 项离线测试。覆盖真实 Qt 标准输入管道、分段读取、间隔持久化、恰好 500 ms、积压的迟到消息、管道关闭、启动无心跳时禁止打开 CAN、既有 STOP 和分包保护。测试入口禁止建立物理 CAN 套接字。

离线通过后，安装程序在遥操进程退出状态获取控制锁，备份旧文件并逐项核对现用文件哈希。安装前后两路 CAN 均为原有的 `UP`，没有启动机械臂或重启现有上位机。现场需关闭已打开的上位机，再用桌面入口加载新版。界面线程持续无响应时仍会触发保护，真机短测待现场进行。
