# 五seed只读分析：Coreset稳定性与Event增量价值

范围：首次seed40–44，Random/Coreset/Event+Coreset均为+IFA、state=True。seed43 repeat1只作单独的重复运行参照，不替换首次结果、不当第六个seed。沿用原AUC/FWT/NBT定义，仅分析已有结果和入库/IFA日志；未训练、未加载模型、未追加环境评估。

C−R为5/5正值，中位数+3.229。排除43仅作敏感性分析，仍为+3.359；任意删除一个seed的四seed均值均为正（+3.359至+6.771）。因此正方向不完全依赖43，但43显著抬高均值。Coreset绝对AUC的跨seed SD为11.022，高于Random的7.733，不能说它降低了运行波动。

seed43 repeat1的C−R为+6.771，而首次为+15.625；EC−C为−5.833，而首次为−16.354。重复结果支持排序方向，未复现原来的大幅优势。不能将硬件/训练数值/评估随机性造成的变化简单归为seed本身。

## 3. Event确实改变记忆，但与Coreset高度重叠

|7|48.11%–49.32%|50%|5–14/740（0.68%–1.89%）|从训练Task8开始|

全部候选中事件自然占比Task6/7/8分别约44.81%/40.14%/34.55%。C本身已经偏向这些事件窗口。Task6已满足事件目标，逐ID退化为C；Task7接近目标，附加干预很小。不能把“Event”当成独立强互补模块已实际作用于全部四阶段。

## 4. 事件配额以普通区域覆盖为代价，但因果尚未隔离

保持相同窗口配额和距离，EC的Task7全局最大覆盖距离比C增加0.37%–1.46%，Task8增加3.79%–6.07%；EC的最大距离均落在普通窗口池。该证据支持“事件配额重新分配了覆盖，牺牲部分非事件区域覆盖”。它不证明被挤出的具体窗口必然关键，更不能把覆盖半径直接当作闭环成功率。

事件检测依据夹爪实际开合和机械臂持续运动模式转换，并未验证这些区间对应接触成功、任务瓶颈或容易遗忘的片段。自然转换不等同于最值得额外存储的样本；原C已使用动作距离，因此两者的信息可能重叠。50%池配额也不等于每个事件等权、每次关键操作均被覆盖。以上是与现有设计/日志相符的解释，不是已识别的唯一因果机制。

时序必须遵守：Task8自身入库发生在其训练之后，不能解释stage8/task8下降；它只能影响后续Task9训练。Task9的记忆选择不能解释当前Task9结果。Task9当前全量训练样本仍相同，差别在旧记忆和由此前训练累积的模型轨迹；因此当前任务损失符合学习/保持取舍或优化轨迹变化，但还混有原评估随机性。

## 5. 不能归因于IFA配对改变，也不能把NBT下降当全面改善

本次从服务器只读核验60份既有event_audit及C/EC IFA文件，所有seed的配对相同：stage6空、stage7仅[6,7]、stage8/9空。Event首次改变Task7存储时stage7训练已结束；后续两个训练阶段没有IFA选中对。因此本轮EC−C差不能解释为Event触发了不同IFA配对。该结论不等同于所有C−R或所有实验都不存在IFA间接作用。

五seed EC−C：FWT下降5.25个百分点，NBT下降2.167个百分点。负NBT既受后续表现影响，也受“刚学完”锚点影响。Task8刚学完平均−6，最终仅−2，便可在绝对表现更差时产生更好的后向变化。因此Event的NBT更低不是额外整体收益证据。

## 6. 结论边界与当前判断

Coreset在已测五seed上的AUC改善方向一致、具有一定稳健性，幅度明显依赖运行；不是仅43异常支撑，但也不是已证明跨套件或重复执行都稳定显著。

当前Event配额方案没有显示稳定的增量AUC收益（2/5提升，3/5下降）。最有数据支持的解释是：C本身已覆盖大量事件；附加约束有效范围有限，并将少量记忆预算从普通控制区域移向规则检测的事件，后期任务学习代价超过收益。覆盖取舍可核验，具体闭环因果不可从这些记录唯一识别。不能进一步推断所有事件方法无效。

每单元仅20条原初态，动作采样随机流未逐轨迹隔离；五seed是探索性扩展，重复初态/单元不能当作额外独立seed。未以已有结果筛选新阈值或设计/启动追加实验。
