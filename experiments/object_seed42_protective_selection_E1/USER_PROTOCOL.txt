**E1 只验证“保护性选样”是否有效：在逐批保持新旧样本数量、旧任务数量分配、训练损失和优化过程不变的条件下，替换部分旧样本的检索方式；直接复用已有 E0 结果，不重跑基线，也不加入动态权重或动态回放比例。**

下面将 E1 固定为一个可交付给代码实现与实验执行的方案。代码定位依据官方仓库 `yfqi/lifelong_mlr_ifa` 的 `a721807` 版本；**实际修改应建立在你已经跑通 E0 的代码版本上，不能为了对齐官方版本而更换基线。**

# 一、实验目标与必须锁定的条件

## 1. 唯一研究问题

> **相同的回放机会和训练设置下，把部分随机旧样本换成“预计有助于整体历史行为、且与新任务冲突较小”的旧样本，能否提高 LIBERO-OBJECT 的总体闭环指标？**

E1 不验证“最小必要回放权重”，也不计算此前的 \(\lambda_{\min}\)。那些属于 E2。

## 2. 从已有 E0 继承的内容

开始前只整理已有工件，不启动任何 E0 训练。

| 项目 | E1 的处理 |
|---|---|
| 代码与环境 | 从跑通 E0 的版本分支，保持依赖、GPU 数量、精度设置不变 |
| 初始化 | 使用 E0 相同的预训练检查点，不重新预训练 |
| 数据 | 相同任务顺序、示范文件、特征文件和预处理 |
| 缓存 | 相同入库规则、容量、每阶段缓存内容；使用独立工作目录，避免覆盖 E0 |
| 训练 | 相同 batch size、epochs、每阶段优化步数、优化器、学习率调度和梯度裁剪 |
| 损失 | 原始 BC＋IFA，系数、归一化和 IFA 配对规则不变 |
| 采样数量 | 每个 batch 的新样本数、旧样本数、各旧任务样本数均保持原规则 |
| 评估 | 相同评估检查点、环境初始状态、试验次数及指标汇总程序 |
| 筛选 seed | 使用已有 E0 的同一个 seed，不另选一个更有利的 seed |

原文的 OBJECT 设置是六个预训练任务、四个增量阶段；增量阶段每个任务十条示范，训练设置包括 batch size 10、100 epochs、AdamW，评估每 seed 20 次试验。这些用于核对已有 E0，**不是在 E1 中单方面修改 E0 实际配置的理由**。Yu 等 - Lifelong imitation learn… Yu 等 - Lifelong imitation learn…

若发现 E0 实际配置与论文不同，应记录差异；不要在 E1 中同时“修正配置＋增加选样”，否则失去归因。

# 二、核心实现：保留原 batch，只替换同任务的旧样本

这是 E1 最重要的实现选择。

官方实现将当前任务特征与旧缓存拼接后交给采样器。因此，直接换成对整个数据集加权的采样器，会同时改变新旧比例，甚至改变旧任务之间的分配，不能作为纯 E1。

## 1. 采用“同任务、原位置替换”

先让原始 DataLoader 正常产生一个 batch。随后，在进入原始 `observe()` 之前，增加一层旧样本替换：

**当前任务样本完全不动。**

**旧任务样本只允许替换成同一个旧任务的其他缓存样本。**

**不改变样本位置、任务编号或 batch 长度。**

例如，原 batch 的任务排列是：

```text
新、旧A、新、旧B、旧A、新、新、旧B、新、新
```

E1 处理后，排列仍然相同，只改变某些“旧A”“旧B”位置对应的具体特征窗口和专家动作。

因此，下面三项是逐批不变量，而不只是长期平均接近：

\[
n_{\mathrm{new}}^{E1}=n_{\mathrm{new}}^{E0},
\]

\[
n_{\mathrm{old}}^{E1}=n_{\mathrm{old}}^{E0},
\]

\[
n_j^{E1}=n_j^{E0},\quad \text{对每个旧任务 }j.
\]

## 2. 一半优先替换，一半保留原始覆盖

首版固定：

- 每个旧样本位置以 **0.5 概率**从该任务的保护性候选分布重新抽样。
- 以 **0.5 概率**保留原 DataLoader 选中的旧样本。

**这里的 0.5 是“旧样本位置的优先替换概率”，不是整个 batch 的旧样本比例。**

保留原样本的分支负责延续原缓存覆盖，避免训练长期局限在少数候选窗口。不要额外加入损失重要性权重；E1 有意改变的是旧样本训练分布，而不是做无偏估计。

# 三、保护性评分的完整定义

## 1. 评分数据全部来自合法的当前数据与旧缓存

每次低频刷新时，构造三类数据：

| 数据 | 首版规模 | 来源与用途 |
|---|---:|---|
| 历史参考集 \(H_j\) | 每个旧任务 16 个窗口 | 从当前合法缓存抽取，估计历史保护方向 |
| 候选集 \(C_j\) | 每个旧任务 64 个窗口 | 从同一缓存抽取，与该次参考集文件 ID 不重叠 |
| 新任务参考集 \(N\) | 16 个窗口 | 从当前任务合法训练数据抽取，估计新任务方向 |

窗口不足时按实际数量缩减，不重复复制来凑数；无法形成有效参考与候选的任务，沿用原随机检索。

这里的“分开”只保证**本次参考与候选不使用同一个缓存条目**，不声称它们属于独立轨迹或独立测试数据。若现有文件没有真实轨迹编号，不通过文件序号猜测轨迹归属。

参考批次不会被额外送入优化器做训练；但其中的样本以后仍可能被原 DataLoader 抽到。因此，它不是留出验证集。

## 2. 只对策略头参数计算评分梯度

设 \(\phi\) 为 GMM 策略头的参数，样本 \(i\) 的评分梯度为：

\[
\widetilde g_i=\nabla_\phi \ell_i^{BC}.
\]

历史参考方向采用任务均衡平均：

\[
\widetilde g_H=
\frac{1}{J}\sum_{j=1}^{J}
\nabla_\phi
\left[
\frac{1}{|H_j|}\sum_{h\in H_j}\ell_h^{BC}
\right].
\]

新任务方向为：

\[
\widetilde g_N=
\nabla_\phi
\left[
\frac{1}{|N|}\sum_{n\in N}\ell_n^{BC}
\right].
\]

然后计算候选分数：

\[
\boxed{
s_i=
\cos(\widetilde g_i,\widetilde g_H)
-
\alpha
\max\left[0,-\cos(\widetilde g_i,\widetilde g_N)\right]
}
\]

首版固定 \(\alpha=1\)。

第一项偏好能改善整体历史参考目标的样本；第二项惩罚与新任务学习方向冲突的样本。

**这个分数是头部梯度排序代理，不是完整策略的保护保证，也不是候选样本实际闭环价值的测量。**

## 3. 在每个旧任务内部形成概率分布

对任务 \(j\) 的候选集：

\[
q_j(i)=
\frac{\exp(s_i/\tau)}
{\sum_{k\in C_j}\exp(s_k/\tau)},
\qquad i\in C_j.
\]

首版固定 \(\tau=1\)，采用数值稳定的 softmax。

此后，该任务的优先替换位置从 \(q_j\) 抽样。**不根据分数重新分配各旧任务的样本数量。**

## 4. 明确退化处理

历史参考梯度范数过小、参考梯度非有限或评分整体无效时，本次刷新不启用优先替换，返回原始检索规则。

新任务梯度无效但历史参考有效时，暂时去掉冲突惩罚，只用历史保护项，并记录该情况。个别候选梯度无效时，将该候选排除；某任务没有有效候选时，该任务保留原样本。

这些规则只改变 **E1 是否进行替换**，不触碰回放权重或数量。

# 四、首轮固定配置：不做参数搜索

以下数值是**本次建议预先固定的起始配置，不是论文参数，也不是已经验证过的最优值**。

```yaml
# 拟新增的 E1 配置字段，需要在本地实现后接入；
# 不是官方仓库已经提供的接口。
e1_selection:
  enabled: true

  refresh_interval_steps: 500
  refresh_at_stage_start: true

  reference_per_old_task: 16
  candidates_per_old_task: 64
  current_reference_size: 16

  priority_replace_probability: 0.5
  conflict_coefficient: 1.0
  softmax_temperature: 1.0
  numerical_epsilon: 1.0e-8

  gradient_scope: policy_head
  preserve_task_slots: true
  fallback: original_retrieval
```

刷新间隔按**实际优化步**计数，不按 epoch，避免不同阶段数据量不同导致频率含义变化。每个有旧缓存的新阶段，在第一次正常优化前刷新一次，然后每 500 步刷新。

两次刷新之间，保留候选 ID、分数与概率，但每次重新抽样，**不是反复使用同一个固定回放 batch**。

首轮直接用这一组配置完成闭环验证，不同时搜索多个温度、替换比例或候选规模。代码正确但总体无收益时，先记录这个版本失败，再决定是否形成下一版修改。

# 五、代码改动位置与实现约束

## 1. 最小代码改动范围

| 位置 | 改动 |
|---|---|
| **新增** `libero/lifelong/replay_selection.py` | 实现候选抽样、头部评分、分布缓存和同任务替换 |
| `libero/lifelong/algos/mlr.py` | 在原训练循环、原 `observe()` 前接入刷新和替换 |
| 配置 | 增加上面的 `e1_selection` 字段，其他配置继承 E0 |
| 独立日志与状态文件 | 保存选样统计、额外耗时和恢复所需的选择器状态 |

在本次核查的官方版本中，训练循环位于 `MLR.learn_all_tasks()`，原更新由 `self.observe(data, current_task_id, epoch, ifa_info=ifa_info)` 执行。E1 应插在这次调用之前，不重写原始优化过程。

逻辑如下，接口名称为拟新增接口：

```python
for epoch in original_epoch_loop:
    original_sampler.set_epoch(epoch)

    for batch in original_dataloader:
        # 仍按原始逻辑获得完整 batch。
        original_task_ids = read_task_ids(batch)

        if old_buffer_is_available:
            if selector.should_refresh(optimizer_step):
                selector.refresh(
                    policy=policy,
                    old_buffer=legal_old_buffer,
                    current_data=current_task_data,
                )

            batch = selector.replace_old_slots(
                batch=batch,
                current_task_id=current_task_id,
            )

        # 当前位置、任务排列和每任务数量不得改变。
        assert_task_slots_unchanged(original_task_ids, batch)

        # BC、IFA、反向传播、裁剪、优化器均保留原实现。
        loss = original_observe(batch)
        optimizer_step += 1
```

## 2. 评分应走“解码器前向＋头部反向”，不是完整网络反向

官方 `BriefPolicy` 使用时序解码器得到末端特征，再送入 GMM 策略头；当前 `GMMHead.loss_fn()` 已提供 `reduction="none"`，并监督窗口末端动作。 

建议评分实现为：

**先在不建立梯度图的情况下得到时序解码器输出，再将输出 detach，计算 GMM 头部的 BC 梯度。** 候选逐个或小块处理，算出分数后立即释放梯度，不把全部候选的长梯度向量一直堆在 GPU 上。

历史参考和新任务参考只需要平均损失的聚合头部梯度，不需要保存各参考样本的完整梯度。

### 两个需要特别避开的代码陷阱

**不要直接调用 `policy.eval()` 后再依赖原 `BriefPolicy.forward()` 评分。** 核查版本的 `forward()` 只在 `self.training` 为真时返回结果。可直接调用 `temporal_encode()` 获取特征，评分期间关闭解码器 dropout，以获得较稳定的排序代理；评分结束后恢复原模式。

**评分要用训练时的完整 GMM 密度，而不是执行动作时的模式选择或低噪声分布。** 训练密度、动作目标切片必须与原 BC 定义一致，否则分数会衡量另一个问题。 

## 3. 不在 E1 中顺手修复其他算法行为

`base.py` 中的 IFA 会读取混合 batch 第一条样本的语言特征作为参考，因此采样改动可能与这段实现相互作用。

E1 应保持位置及任务编号，并检查同任务替换前后的该语言参考是否一致。若第一位置的参考不能保持一致，就不替换该位置。

**不要只在 E1 中修复 IFA，再把结果与未修复的 E0 比较。**

# 六、正式训练前，只做短检查，不重跑 E0

以下是实现验收，不是一组新的基线实验。使用少量 batch 或临时模型状态检查，结束后丢弃测试状态，正式运行从规定起点开始。

## 1. 数据与采样不变量

检查替换前后：

\[
\text{batch 长度、任务 ID 序列、当前样本内容}
\]

完全不变；每个替换条目的特征与动作必须来自同一个合法缓存文件，不能只换特征不换标签。

同时确认，候选与参考只能读取**该阶段已经允许保留的缓存**，不能扫描完整旧任务特征目录来找更好的样本。

## 2. 评分不产生训练更新

一次 `refresh()` 前后应满足：

- 模型参数、优化器状态没有改变。
- 不执行 `optimizer.step()`。
- 不污染随后正常训练使用的梯度。
- 模块训练/评估状态被完整恢复。

关闭 E1，或者把优先替换概率设为零时，给定相同 batch，应退化为原更新路径。

## 3. 随机数隔离

参考抽样、候选抽样和替换使用独立随机数生成器，不消耗原数据采样与入库使用的随机数流。评分操作涉及的全局随机状态也要恢复。

否则，即使 seed 相同，也可能因为新增了几次随机抽样而改变后续入库文件或训练数据顺序，导致 E1 不再是单一改动。

## 4. 缓存与恢复状态

E1 使用独立缓存工作目录，并保存每阶段缓存文件清单或内容哈希。比较 E0 与 E1 时，以样本内容和逻辑 ID 为准，不因实验目录不同而误判缓存变化。

**不能将 E0 最终阶段的完整缓存直接作为 E1 初始缓存。** 那会提前暴露未来任务数据。

恢复训练时还应保存选择器的候选 ID、概率、上次刷新步数和独立随机状态；这些放在旁路状态文件中，不破坏原评估器读取模型检查点的格式。

# 七、正式执行顺序与闭环验证

## 阶段 A：冻结 E1 实现与运行清单

记录已有 E0 的代码版本、配置、seed、预训练权重哈希、示范清单和评估配置；随后冻结 E1 配置及代码差异。

**允许变化的清单只有：选样模块及其必要日志、状态和独立输出目录。**

实际启动命令沿用你已经跑通 E0 的命令，只接入新增选择器配置和 E1 输出位置。这里不臆造你本地的 launcher、检查点路径或 seed 编号。

## 阶段 B：固定单 seed，运行完整 E1 序列

不训练 E0、不重新预训练。E1 从相同预训练起点完成 OBJECT 的四个增量阶段。

官方构造数据集时，第一个增量阶段只使用当前任务数据；因此在这一阶段 E1 自动旁路，后续出现旧缓存后才启用。

这仍属于 E1 完整序列，不是新增一遍 E0 对照。已有第一阶段产物只有在模型、缓存及后续所需随机状态等均可等价恢复时才能复用，不能直接拿 E0 最终模型继续训练。

训练中不因某个任务损失较好而提前结束，也不根据闭环测试成绩在线调整选样概率。

## 阶段 C：按原检查点规则完成真实闭环评估

使用 E0 的同一评估程序和检查点规则，保留相同任务集合、评估状态、rollout 次数及成功判断。

**不要只评最终模型，也不要只评当前新任务；必须取得原指标所需的完整历史成功率记录。**

本次核查的官方评估脚本会遍历阶段检查点与已经引入的任务，且包含具体 epoch 范围。E1 应复用你 E0 已采用的规则，不另选一个对 E1 最有利的检查点范围。

另外，训练代码在关闭训练内评估时会将 success 设置为占位值，因此训练返回值或损失日志不能代替闭环指标。

## 阶段 D：只与已有 E0 做总体比较

主结果表固定为：

| 版本 | 总体 AUC ↑ | 总体 FWT ↑ | 总体 NBT ↓ | 训练总耗时 | 其中选样额外耗时 |
|---|---:|---:|---:|---:|---:|
| E0，同一 seed | 读取已有结果 | 读取已有结果 | 读取已有结果 | 读取已有日志 | 无 |
| E1，同一 seed | 新实验 | 新实验 | 新实验 | 实测 | 实测 |
| E1−E0 | 差值 | 差值 | 差值 | 差值 | — |

指标定义和聚合方式严格沿用原论文及核定的 E0 实现；原论文 AUC 是先计算各任务引入后的平均表现，再对任务平均，不能随意替换成所有成功率条目的直接平均。Yu 等 - Lifelong imitation learn…

建议预先固定**总体 AUC 为主终点，总体 FWT、NBT 用来判断整体取舍**，不事后改变三者的优先级，也不临时构造加权综合分数。

单任务结果、候选评分、参考损失和重复抽样率只负责解释，不单独决定保留或否定 E1。

## 阶段 E：有总体收益后，补齐三 seed

单 seed 总体结果值得保留时，锁定代码与超参数，补跑另外两个预定 seed，报告三 seed 均值、标准差及逐 seed 的配对差值。

**单 seed 的 AUC 上升只是继续验证的依据，不是稳定有效的证明。**

使用已有对应 seed 的 E0 结果比较，不自动重跑基线。若现有 E0 缺少对应 seed，则明确配对证据不足，不能把三 seed 的 E1 与单 seed 的 E0 当成完全等价的比较。

若总体没有改善，即使保护分数变高或某个任务提升明显，也不能宣布 E1 有效，更不立即叠加 E2 来掩盖问题。

# 八、本轮必须留下的实验工件

本轮结束后应具备四类结果：

**可复现工件：** E1 代码差异、完整配置、E0 工件引用、seed、预训练权重哈希、各阶段缓存清单，以及选择器恢复状态。

**主结果：** 与 E0 同口径的总体 AUC、FWT、NBT，完整闭环成功记录和检查点对应关系。
